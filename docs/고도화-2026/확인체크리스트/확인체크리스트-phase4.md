### 1. 🔴 수정이 신규등록으로 새어나가던 버그 — 수정 완료

`BoardPostForm.tsx` — 스토어의 `editSq` 를 그대로 읽어 `isEdit` 을 판정하고 있었다.
같은 컴포넌트의 언마운트 cleanup `resetBoard()` 가 **StrictMode 이중 마운트에서 한 번 먼저

→ 원본은 그대로 남고 **새 글이 하나 더 생겼다.**

수정: 다른 필드와 똑같이 첫 렌더에 값을 붙잡는다.
```ts
const [editTargetSq] = useState(editSq)   // 스토어가 리셋돼도 살아남는다
const isEdit = editTargetSq > 0
```
`PUT` URL 도 `editTargetSq` 를 쓰게 바꿨다.

### 🔴 이번에 새로 발견 — 수정 모드가 수정이 아닐 수 있다 (미확정)

수정 폼에 들어갔는데 **제출 버튼 라벨이 "수정"이 아니라 "등록"** 으로 떴다.
`BoardPostForm.tsx:420` 이 `{isEdit ? '수정' : '등록'}` 이므로, 이는 `isEdit === false`
= `editSq === 0` 이라는 뜻이다. 그러면 `handleSubmit` 이 PUT이 아니라 **POST 로 가서
수정 대신 새 글이 하나 더 생긴다.**

의심 원인 — `BoardPostForm.tsx:101~103`
```
useEffect(() => { return () => { resetBoard() } }, [resetBoard])
```
React StrictMode(dev 기본값)는 mount → **unmount** → mount 로 이펙트를 두 번 돌린다.
그 중간 unmount에서 `resetBoard()` 가 돌아 `editSq` 가 0으로 밀린다.
제목·본문은 `useState(boardData.ttl)` 로 **첫 렌더 때 이미 복사**돼서 화면에는 멀쩡히
남아 있고, `editSq` 만 죽는다. → 프리필은 되는데 저장은 신규등록.

- **Phase 4 회귀는 아니다.** `resetBoard` cleanup 도 `isEdit` 판정도 Phase 4 이전 코드다
  (`git diff 08c72d8c..HEAD` 에 두 줄 모두 없음). 카테고리 때문에 수정 화면을 처음
  자세히 봐서 드러난 **기존 버그**로 보인다.
- **dev 전용일 수 있다.** StrictMode가 원인이면 프로덕션 빌드에서는 재현되지 않는다.
- **확정 방법(다음 작업 1번)**: 지금 수정 폼에서 저장 눌러보고 글 수를 비교.

5. **메인·커뮤니티 허브 베스트글 육안 + ⓘ 팝오버 문구** (항목 6 잔여분)
6. 정리: 검증용 글 **sq 164** 삭제 (시드 156~163은 그대로 둘 것)

### 🤔 새로 생긴 판단 필요 1건 — 전체보기의 카테고리 뱃지

`/community/list`(전체보기)는 일반게시판 + Q&A 를 섞어 보여주는 화면인데,
일반게시판 글에만 `[자유] [현장정보]` 접두 뱃지가 붙고 Q&A 글에는 안 붙는다.
칩 필터 줄이 없다는 조건은 지켰지만, 한 목록 안에서 어떤 줄에만 뱃지가 붙는 모양이 된다.
→ **그대로 둘지 / 전체보기에서는 뱃지도 뺄지** 결정 필요.

## 📌 "베스트글 무회귀"가 뭘 확인하는 건지 (사용자 질문 답변)

Phase 3에서 베스트글 **집계 대상을 SQL로 못 박고, 그 기준을 화면 문구로 명시**했다.
`BoardMapper.findBestBoards` 의 `WHERE ... board_type_cd IN (1401, 1402)` —
**자유게시판(1401)과 Q&A(1402)만 집계, 공지(1403)는 제외**다.
그리고 `BestCriteriaInfo.tsx`·`PopularWidget.tsx` 가 "자유게시판·Q&A만 집계, 공지 제외"라고
사용자에게 안내한다. **SQL과 문구가 어긋나면 Phase 3-B가 거짓말이 된다.**

Phase 4가 `BoardMapper.xml` 을 건드렸으니 그게 깨졌는지 보는 것이다. 구체적으로:

1. **메인/커뮤니티 허브의 베스트글·인기글 목록이 Phase 4 전과 같은지** — 항목 수와 순서
2. 그 목록에 **공지사항 글이 섞여 있지 않은지**
3. 팝오버(ⓘ) 안내 문구가 여전히 "자유게시판·Q&A만 집계, 공지 제외"인지
4. `GET /api/community/best?period=all&size=5` 응답에 `boardType` 이 `board`/`qna` 뿐인지

> **결론부터: 이번 작업에서 `findBestBoards` 쿼리는 한 줄도 건드리지 않았다.**
> `board_type_cd` 체계도 그대로다(카테고리는 별도 컬럼 `board_category_cd`).
> 그래서 회귀 가능성은 낮지만, 같은 파일을 수정했으니 **눈으로 한 번 보는 것이 이 항목의 목적**이다.

## 사용자 육안 확인이 필요한 것 (5건)

### 1. 목록 뱃지 — 카테고리 있는 글이 실제로 보이는지
`/board` 에서 카테고리를 지정해 글을 하나 등록한 뒤:
- 데스크톱(md 이상): 제목 앞에 `[현장정보]` 접두 뱃지
- 모바일(375px 에뮬레이션): 카드 상단에 `일반` 뱃지 옆으로 카테고리 칩
- **미분류 기존 글에는 아무 뱃지도 없어야 한다** (자유로 승격하지 않음)

### 2. 상세 화면 뱃지 + 수정 인계
그 글 상세로 들어가서:
- 제목 위에 카테고리 칩
- **수정** 버튼 → 작성 폼에 카테고리가 **미리 선택된 상태**로 뜨는지
- 수정 모드에서는 카테고리를 바꿔도 **양식이 주입되지 않아야 한다** (기존 글 보호)

### 3. Q&A·공지에는 카테고리가 안 보여야 한다
- `/qna`, `/community/list`(전체보기), `/notice` — 카테고리 칩 줄이 **없어야** 한다
- `/qna/register` 작성 폼에도 카테고리 select 가 **없어야** 한다

### 4. BO 게시물 관리 (5173)
`관리 > 게시물 관리`:
- 목록에 **카테고리** 컬럼(유형 다음). 답변·Q&A 행은 `-`
- 툴바에 **카테고리** 필터 → 다중 선택 → 목록·건수 함께 줄어드는지
- **게시글 유형 필터와 카테고리 필터를 동시에** 걸었을 때 한쪽이 초기화되지 않는지 ← 특히 확인
- 카테고리 컬럼 헤더 클릭 정렬
- 글쓰기: 유형 = **일반 게시글**일 때만 카테고리 select 노출, Q&A 로 바꾸면 사라지는지
- BO에서 카테고리 지정해 등록 → FO `/board` 목록에 그 카테고리로 보이는지

### 5. 베스트글 무회귀 (Phase 3 인계 1번 항목)
- 메인/커뮤니티 허브의 베스트글·인기글이 이전과 동일하게 나오는지
- 팝오버 안내 문구("자유게시판·Q&A만 집계, 공지 제외")가 여전히 맞는지
  → `findBestBoards` 의 `IN (1401,1402)` 는 **손대지 않았다**

## 컨펌이 필요한 판단 4건

### ① '자유'와 '일반' 카테고리 이름이 헷갈린다
게시판 이름 자체가 **"일반 게시판"** 인데 그 안에 **'자유'** 와 **'일반'** 카테고리가 같이 있다.
사용자에게 "일반 게시판의 일반 카테고리"는 무슨 뜻인지 설명하기 어렵다.

Phase 1에서 공통코드로 이미 넣은 값이라 그대로 구현했고, **FO가 라벨을 서버에서 받아 쓰므로
이름 변경은 공통코드 `UPDATE` 한 줄로 끝난다(코드 수정·재배포 불필요).**

→ 그대로 갈지, 이름을 조정할지 결정 필요. 조정한다면 공용 DB UPDATE 라 승인 후 실행.

### ② 기존 글 75건을 백필할지
현재 전부 `board_category_cd = NULL`(미분류)이고, 목록에 뱃지가 안 붙는다.
- **그대로 두기(현재)** — 미분류와 실제 '자유' 선택을 구분할 수 있다. 다만 카테고리 탭
  '자유'를 눌러도 기존 글은 안 나온다.
- **전부 3201(자유)로 백필** — 카테고리 탭이 처음부터 채워져 보인다. 되돌리려면
  "원래 NULL이던 행"을 따로 기록해 둬야 한다.

→ Phase 8 봇 더미데이터로 각 카테고리가 채워질 예정이라 **그대로 두는 쪽을 권장**한다.

### ③ 현장정보 양식 항목이 이게 맞나
현재: **현장명 / 위치 / 공정 · 업무 / 근무 조건(기간, 근무 시간, 단가·급여) / 참고 사항**
계획서에 적힌 항목 그대로다. 실제 현장 글에 필요한 항목이 더 있으면 알려달라
(`components/community/boardTemplates.ts` 한 파일만 고치면 된다).

### ④ 카테고리를 필수로 만들지
현재는 **선택**이다(미선택 = 미분류). 필수로 하면 분류율이 올라가지만 글쓰기 마찰이 늘고,
기존 글이 전부 미분류라 정책이 일관되지 않는다.

→ 현재대로 선택 유지를 권장. 필수로 바꾸려면 FO 검증 + `BoardRequest` 에 `@NotNull` 추가.

## 다음 Phase에 넘기는 사항

### 🔴 Phase 5 착수 전 반드시 처리 — BO의 1404 코드 충돌
`AdminBoardMapper.xml` 은 **답변(Answer) 행에 가짜 타입코드 `1404` 를 붙인다**
(`1404 AS boardTypeCd`, UNION ALL 양쪽). BO 프론트도 `1404 = '답변'` 으로 매핑한다
(`board-columns.tsx:68`, `board-table.tsx:125`, `board-mutate-drawer.tsx` 3곳,
`board-view-drawer.tsx` 4곳).

그런데 **Phase 1에서 공통코드 1404를 '고객의소리(VOC)'로 등록했다.**
그리고 이 쿼리는 `board_type_cd != 1403` 으로만 걸러서 **VOC 글(1404)이 BO 목록에 들어오고,
'답변'으로 표시된다.** Phase 5에서 VOC 글이 생기는 순간 터진다.

Phase 4 범위가 아니라 **손대지 않았다**(BO 7곳 + 매퍼를 함께 바꿔야 하고 회귀 범위가 넓다).
답변/게시글 구분은 이미 `mainType`('BOARD'|'ANSWER') 컬럼이 하고 있으므로,
가짜 코드를 사용하지 않는 미사용 번호(예: `9001`)로 옮기거나 `mainType` 기준으로 정리하면 된다.

### 그 밖에
- **`JwtAuthenticationFilter.EXCLUDE_URLS`** 가 `SecurityConfig` 와 별개인 **두 번째 화이트리스트**다.
  Phase 5의 `/voc/**` 는 인증 필요라 오히려 목록에 **넣지 말아야** 하고, VOC 카테고리 조회처럼
  공개 GET을 새로 만들면 **양쪽에** 넣어야 한다. 이 필터는 **접두사 매칭**이고,
  **매핑 없는 경로도 401로 만든다**(404가 아니라 401이 나와 원인 추적이 어렵다).
- **PATCH 계열 `@Valid` 누락** 확인은 이번에도 못 했다(Phase 3 인계 4번). 게시글 API는
  `@ModelAttribute` + 서비스 내부 수동 검증 방식이라 `@Valid` 자체가 없다.
- `BoardMapper.update` 는 카테고리를 무조건 덮어쓴다. `updateStatusBoard` 는
  `SELECT *` 로 읽은 엔티티를 넘기므로 보존되지만, **새 호출부를 만들 때 주의**할 것.
