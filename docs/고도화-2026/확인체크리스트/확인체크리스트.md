## 2. 길찾기 — 예전 방식 복원 + 보안 검토 결과

원복했습니다. 삭제: `app/directions/`, `lib/kakaoMap.ts`. 되돌림: `proxy.ts`, `types/index.ts`, `ProjectDetailResponse`의 좌표 필드.

### 요청하신 보안 검토

**결론부터: 이 방식 때문에 새로 생기는 심각한 취약점은 없습니다.** 다만 알고 계셔야 할 게 하나 있습니다.

| # | 항목 | 판정 |
|---|---|---|
| 1 | **목적지 좌표 노출** | 문제 없음. 프로젝트 근무지는 공고에 공개된 정보이고, 목록 API가 이미 좌표를 내려준다 |
| 2 | **사용자 좌표 노출** | ⚠️ **아래 설명 참고** |
| 3 | **오픈 리다이렉트** | 없음. 도메인이 `map.kakao.com`으로 하드코딩되어 있고 사용자 입력이 도메인에 끼어들 수 없다 |
| 4 | **URL 주입** | 막음. 프로젝트명은 `encodeURIComponent`, 좌표는 `Number.isFinite` 검증을 통과해야 링크를 만든다 |
| 5 | **역탭내빙(reverse tabnabbing)** | **기존에 있던 문제 → 이번에 막음.** `window.open(url,'_blank')`은 열린 탭에 `opener` 참조를 넘겨서, 상대 페이지가 우리 탭을 다른 주소로 바꿔치기할 수 있었다. `noopener` 추가 |
| 6 | **Referer 누출** | **기존에 있던 문제 → 이번에 막음.** 우리 페이지 URL이 카카오로 전달됐다. `noreferrer` 추가 |
| 7 | **XSS** | 별개로 이번에 막음 — 지도 마커 툴팁이 제목·회사명·주소를 raw HTML로 삽입하고 있었다 |

#### ⚠️ 알고 계셔야 할 것 — 그 좌표는 "현재 위치"가 아니라 "등록 주소"입니다

코드를 따라가 보니 `userStore`의 `latitude/longitude`는 브라우저 GPS가 아니라 **`/me` API가 내려주는 회원가입 시 입력한 주소의 좌표**입니다.

즉 URL에 실리는 값은 **사용자의 등록 주소(집/회사)** 이고, 이건:
- 브라우저 **방문 기록**에 남습니다 → 공용 PC·가족 공용 PC에서 다음 사람에게 보일 수 있습니다
- 카카오 서버 로그에 남습니다 (지도 서비스라 어차피 위치를 받긴 합니다)

실시간 위치보다 오히려 고정적이라는 점에서 덜 민감하다고 보기 어렵습니다. **그래도 진행하겠다는 판단이시면 그대로 두면 됩니다** — 길찾기 기능의 성격상 불가피한 부분이 있고, 위 5·6번을 막아서 예전보다는 나은 상태입니다.

혹시 신경 쓰이시면 나중에 선택 가능한 대안: 출발지를 좌표 대신 `내 위치` 문자열만 넘기거나(카카오가 직접 잡게), 마이페이지에 "길찾기에 내 주소 사용" 토글을 두는 방식이 있습니다. 지금 당장 할 일은 아닙니다.

## 3. svg 허용 — 함께 막은 것

svg를 허용했습니다. 그런데 코드를 보다가 **그냥 허용하면 실제로 위험한 경로**를 발견해서 같이 고쳤습니다.

### 발견한 것
`FileController`가 `download=false`일 때 `Content-Disposition: inline`으로 응답합니다. 즉 `.svg` 파일을 주소창에 직접 열면 브라우저가 **문서로 렌더링**하고, 안에 든 `<script>`가 **우리 사이트 권한으로 실행**됩니다.

그리고 `accessToken` 쿠키가 httpOnly가 아닙니다 (`lib/api.ts`가 `document.cookie`로 읽고 있습니다). 그래서 악성 svg 하나로 **로그인 토큰 탈취**까지 갈 수 있는 경로였습니다.

### 막은 방법
`FileController` 응답에 두 헤더를 추가했습니다.
- `Content-Security-Policy: sandbox` — 응답을 격리된 오리진으로 취급해 스크립트 실행·쿠키 접근을 차단
- `X-Content-Type-Options: nosniff` — 확장자와 다른 타입으로 추측 렌더링되는 것 차단

**이미지 표시에는 영향이 없습니다.** `<img>`로 넣은 이미지는 원래 스크립트가 실행되지 않고, sandbox는 문서로 열릴 때만 적용됩니다.

> ⚠️ **이 두 헤더는 svg 허용과 한 쌍입니다.** 나중에 누가 지우면 그 순간 저장형 XSS가 됩니다. 코드에 주석으로 남겨뒀습니다.

### 실제로 테스트한 것
- `<script>alert(document.cookie)</script>`가 든 svg 업로드 → **200 저장됨** (허용 확인)
- 그 파일 서빙 헤더 → `Content-Type: image/svg+xml`, `Content-Security-Policy: sandbox`, `X-Content-Type-Options: nosniff` (격리 확인)
- `.exe` 업로드 → 여전히 **400 + 한글 사유**
- 기존 파일 8건 서빙 확인 → png/gif/jpeg/pdf/svg 전부 정상 타입, `octet-stream` 0건이라 **nosniff로 인한 이미지 깨짐 없음**
- 검증용 게시글은 전부 soft delete로 정리했습니다

- [v] **길찾기** — 프로젝트 목록 → 지도 → 핀 → "경로 찾기" 클릭 시 카카오 지도에 출발지·목적지가 모두 채워지는지

- [v] **툴팁** — 첨부파일/태그 옆 ⓘ 아이콘에 마우스 올리거나 클릭 시 안내가 뜨는지 (**모바일에서 탭으로 열리는지도**)
- [v] **모바일 375px** — 프로젝트 상세에서 제목·지원하기 버튼이 맨 위에 오는지
- [v] **모바일 375px** — 캘린더 월 뷰에서 일정 제목이 칸을 안 넘치는지
- [v] **svg 업로드** — 실제로 svg 첨부해서 글 올려보기
- [v] **기존 이미지** — 게시글 첨부 이미지·프로필 사진이 여전히 잘 보이는지 (nosniff 영향 확인)
