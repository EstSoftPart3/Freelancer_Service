## ① 컨펌 — 제가 판단해서 정한 것들

### C-1. 봇 닉네임은 사람처럼, 식별은 `user_id`로
닉네임을 `현장지기_01`처럼 번호를 붙이지 않고 `현장지기`·`공정관리`처럼 자연스럽게 뒀습니다.
대신 **로그인 아이디를 `bot_01`~`bot_05`로** 통일했습니다.

> **왜:** FO는 Phase 2 이후 닉네임만 노출하고 `user_id`는 BO에서만 보입니다. 닉네임에 번호를
> 붙이면 이용자 눈에 "봇이 쓴 글"로 보여 커뮤니티 신뢰도가 떨어집니다. 회수 근거는 닉네임이 아니라
> **`user_sq` 범위**이고, 스크립트가 생성 직후 그 범위와 일괄 삭제 SQL을 출력합니다.
> → 봇임을 드러내는 게 낫다고 보시면 닉네임 규칙을 바꾸겠습니다.

### C-2. 프로젝트 "등록"은 BO에 만들지 않았습니다
조회·수정·삭제·복구만 있습니다.

> **왜:** 프로젝트 등록은 소속·주소(좌표·지역코드)·기술태그·모집직군이 함께 만들어져야 합니다.
> BO에서 반쪽만 만들면 **검색과 지도에서 보이지 않는 유령 공고**가 생깁니다. 계획서 권고와도 같습니다.

### C-3. 프로젝트 수정 범위를 좁혔습니다
수정 가능: **제목 · 단가(협의 여부) · 모집기간 · 수행기간 · 상세설명 · 우대사항**
수정 불가(읽기 전용): **주소 · 기술태그 · 모집직군**

> **왜:** 주소는 좌표·지역코드가 함께 움직여야 하고(지도 검색과 거리 계산이 그 값을 씁니다),
> 태그·직군은 별도 테이블이라 하나만 바꾸면 검색 필터에서 사라지는 공고가 됩니다.
> 그쪽은 등록자가 서비스 화면에서 고치는 게 안전합니다.

### C-4. 프로젝트 삭제는 논리 삭제 + 복구 가능
목록의 "삭제 포함" 스위치를 켜면 삭제된 공고가 보이고, 되살릴 수 있습니다.

> **왜:** 지원 이력(`TBL_PROJECT_APPLICATION_H`)이 프로젝트를 참조합니다. 행을 지우면
> 지원자의 지원 내역이 깨집니다. 실수로 지웠을 때 복구할 길도 필요합니다.

### C-5. 소속 관리는 새 API 없이 기존 것을 씁니다
백엔드 신규 엔드포인트 0개. 수정 폼도 유저 관리에서 쓰던 다이얼로그를 그대로 재사용합니다.

> **왜:** 573줄짜리 폼을 복제하면 사업자 인증 규칙이 두 곳으로 갈라져 한쪽만 고쳐집니다.
> 다만 **목록에 서버 페이징이 없습니다**(API가 조건에 맞는 소속을 한 번에 다 줍니다).
> 현재 22건이라 문제없고, 수백 건을 넘기면 그때 서버 페이징으로 바꾸면 됩니다.

### C-6. 깨진 메뉴를 하나 제거했습니다
사이드바 "프로모션 & 이벤트 > 활동 랭킹 집계"(`/events/ranking`)는 **라우트가 없는 링크**였습니다.
누르면 404로 떨어져 "관리자 페이지가 고장났다"로 읽히므로 메뉴에서 뺐습니다(코드는 주석으로 남김).

## ② 육안검증 — 브라우저로 봐주실 것 10건

### 준비
```
백엔드  cd backend && ./gradlew bootRun          (8080)
BO      cd frontend/react_js && npm run dev      (5173, admin / {{ADMIN_PW}})
FO      cd frontend/nextjs && npm run dev:clean  (3000)
```

### V-1. 소속 관리 — 목록
BO 좌측 **유저 관리 > 소속 관리**
- 22건이 보이고 **인증완료/미인증 뱃지**, **소속원 수**가 표시되는지
- 소속원 0명인 곳(엘지전자·엠씨에스컨설팅 등)이 회색으로 구분되는지
- 검색창에 **대표자명이나 사업자번호**를 넣어도 걸리는지 (전에는 소속명만 검색됐습니다)
- "사업자 인증" 필터로 미인증만 골라지는지

### V-2. 소속 관리 — 수정
소속명을 클릭 → 수정 다이얼로그가 열리고 → 값을 바꿔 저장 → **목록에 반영되는지**

> 유저 관리에서 쓰던 폼과 같은 것입니다. 주소 검색·사업자 인증 버튼이 정상 동작하는지도
> 함께 봐주세요(같은 컴포넌트라 회귀 가능성은 낮지만 진입 경로가 새로 생겼습니다).

### V-3. 프로젝트 관리 — 목록
BO 좌측 **프로젝트 관리 > 프로젝트 목록**
- 30건, **모집중/모집예정/마감** 뱃지가 기간과 맞는지
- 소속명·지원 건수·조회수가 표시되는지
- 정렬(등록일·단가·지원)이 동작하는지

### V-4. 프로젝트 관리 — 모집 상태 필터
"모집 상태" 필터로 **모집중**을 고르면 2건만 나오는지. (API로는 모집중 2 / 예정 0 / 마감 28 =
전체 30건으로 확인했습니다. 화면 숫자가 이와 맞는지 봐주세요.)

### V-5. 프로젝트 수정
프로젝트명을 클릭 → 우측 패널에서 **제목·단가·기간·설명**을 바꿔 저장 → 목록에 반영되는지.
**"협의 가능"을 체크하면 단가 입력이 비활성**되는지.

### V-6. 🔴 프로젝트 날짜 규칙
수정 패널에서 **모집 종료일을 수행 종료일보다 뒤로** 잡고 저장해보세요.
→ **"모집 종료일이 수행 종료일보다 늦을 수 없습니다."** 빨간 토스트가 떠야 정상입니다.

반대로 **모집 종료 > 수행 시작**(수행 중 추가 모집)은 **저장되어야** 합니다.
Phase 3에서 확정한 규칙이고, 실측상 이 서비스에서는 다수 패턴입니다.

### V-7. 프로젝트 삭제 → 복구
- 삭제 아이콘 → 확인 → **목록에서 사라지는지**
- 우측 상단 **"삭제 포함" 스위치**를 켜면 취소선과 함께 다시 보이는지
- 복구 아이콘(↺)으로 되살아나는지

> API로 확인했습니다(삭제 후 30→29건, 삭제 포함 42건, 복구 후 30건). 화면 동작만 봐주세요.
> **참고: 삭제 포함을 켜면 42건이 나옵니다** — 이전부터 삭제 상태였던 공고가 12건 있습니다.

### V-8. 🔴 FO 무회귀 — 프로젝트 목록
BO에서 삭제한 공고가 **FO `/projects` 목록에서도 사라지는지**, 복구하면 다시 보이는지.
BO 수정한 제목·단가가 FO 상세에 반영되는지.

> BO와 FO가 같은 테이블을 보므로 여기서 어긋나면 조건이 다르다는 뜻입니다.

### V-9. 관리자 권한 강화 무회귀
BO의 **모든 메뉴**를 한 번씩 열어보세요(대시보드·유저·소속·프로젝트·게시글·공지·고객의소리·신고).
전부 정상 로딩되면 됩니다.

> 관리자 API 7개에 `@PreAuthorize`를 걸었습니다. 잘못 걸렸다면 **403이 뜨면서 화면이 빕니다.**
> API로는 확인했지만(관리자 토큰 200, 개인 계정 403) 화면 단위로 한 번 훑어봐주세요.

### V-10. 사이드바
- **유저 관리** 아래 "소속 관리"가 보이는지
- **프로젝트 관리 > 프로젝트 목록**이 새로 보이는지
- **"프로모션 & 이벤트" 그룹이 사라졌는지** (깨진 링크라 제거 — C-6)
