## R-1. 소속 목록 정렬 (V-1)

**BO → 유저 관리 → 소속 관리**
- 컬럼 헤더(소속명·대표자·소속원·사업자 인증 등)를 눌러 **오름차순/내림차순이 바뀌는지**
- 정렬한 상태에서 페이지를 넘겨도 유지되는지

> **원인**: 이 표는 목록을 한 번에 다 받아 화면에서 자르는 구조인데, 정렬 상태와 정렬 모델을
> 테이블에 넘기지 않아 헤더를 눌러도 아무 일이 없었습니다. 화면에서 직접 정렬하도록 붙였습니다.

## R-2. FO 소속 상세 — 기업 URL (V-2 추가 요구)

**FO → 소속(`/affiliation`) → 아무 기업 카드 클릭**
- 다이얼로그에 **기업 URL** 줄이 보이는지 (URL이 등록된 기업만 — 카카오·네이버·이에스티소프트 등)
- 클릭하면 **새 탭으로** 해당 사이트가 열리는지
- URL이 없는 기업에서는 그 줄이 아예 안 나오는지

> DB에 `estsw.co.kr`, `www.kakaocorp.com`처럼 **`https://`가 없는 값**으로 저장돼 있었습니다.
> 그대로 링크에 넣으면 사이트 내부 경로로 해석돼 404가 나서, 스킴이 없으면 붙여주도록 했습니다.

## R-3. 🔴 모집 상태 — 종료일 당일 (V-4 원인)

**BO → 프로젝트 관리 → "모집 상태" 필터 → 모집중**

**말씀하신 "API 2건 vs 화면 0건"의 정체**: 체크리스트에 적어둔 "2건"은 제가 **7/30에 측정한 값**이었고,
7/31에는 API도 화면도 똑같이 0건이었습니다. 화면은 정상이었습니다.

**다만 그 과정에서 진짜 문제를 찾았습니다.** 모집일 컬럼은 시각이 없는 날짜인데 현재 시각과
비교하고 있어서, **종료일 당일 자정부터 마감**으로 잡혔습니다. "오늘까지 모집"인 공고가 아침부터
지원마감으로 보이던 겁니다.

날짜 기준으로 바꿨습니다. 확인해주실 것:
- **모집중 2건**이 나오는지 (sq 116·113 — 둘 다 **오늘(7/31) 종료**인 공고입니다)
- FO `/projects` 목록에서도 그 두 건이 **"채용중"**으로 보이는지 ← BO만 고치면 어긋나므로 함께 고쳤습니다

## R-4. 필터 다중 선택 (V-4)

**BO → 프로젝트 관리 → "모집 상태" 필터**
- **모집중 + 마감**을 함께 고르면 → 둘 다 선택된 채로 유지되고 **29건**이 나오는지
- 셋 다 고르면 전체(29건)가 나오는지

**BO → 고객의 소리 → "처리 상태" 필터**
- **미답변 + 답변완료**를 둘 다 골라도 **선택이 풀리지 않는지** (결과는 전체와 같습니다)

> 프로젝트는 서버가 상태를 여러 개 받도록 바꿨습니다. 고객의 소리는 서버가 여전히 하나만 받지만
> (둘 다 = 전체라 의미가 같습니다) **선택 표시는 유지**되게 했습니다 — 전에는 두 번째를 고르는 순간
> 선택이 통째로 풀려서 조작이 잘못된 것처럼 보였습니다.

## R-5. 단가 + 협의 가능 동시 입력 (V-5)

**BO → 프로젝트 관리 → 아무 공고 → 상세 패널**
- 단가에 **3000000**을 넣고 **"협의 가능"도 체크**한 뒤 저장 → 둘 다 저장되는지
- 목록의 단가 칸 표시 확인

**FO 확인** (원래부터 되고 있었습니다):
- 마이페이지 → 프로젝트 등록: 단가 입력과 "단가 협의" 체크가 **동시에** 되는지
- 프로젝트 상세: **`단가 : 3,000,000원 / 단가 협의`** 로 함께 표시되는지
- 프로젝트 카드: 단가 + **"단가협의 가능"** 뱃지가 함께 붙는지

> FO는 등록·표시 모두 이미 동시 지원이었고, **BO만** 협의 체크 시 단가를 잠그고 저장에서
> 빼고 있었습니다. 그 제한을 없앴습니다.
