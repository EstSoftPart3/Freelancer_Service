## B. Phase 3에서 얻은, Phase 4에 영향 있는 사실

1. **`BoardMapper.findBestBoards`는 `board_type_cd IN (1401, 1402)`로 집계한다.**
   Phase 4가 게시판 카테고리를 도입하면서 타입 코드 체계를 건드리면 **베스트글 집계 범위가 조용히
   바뀐다.** 그리고 Phase 3에서 안내 문구에 "자유게시판·Q&A만 집계, 공지 제외"라고 **명시했기 때문에**,
   SQL이 바뀌면 문구가 거짓이 된다. 둘을 함께 봐야 한다.

2. **동적 검색 조건은 목록·카운트·지도가 따로 논다.** `ProjectMapper`에서 목록만 `'회사명'`을
   지원하고 카운트·지도는 `'작성자명'`인 채로 남아 있었다. **`<choose>`를 고칠 때는 짝이 되는
   count 쿼리를 반드시 함께 grep 할 것.** 커뮤니티 쪽도 같은 구조일 가능성이 높다.

3. **`@Valid` 검증 실패가 이제 400 + 한글 사유로 나간다**(Phase 3에서 핸들러 추가).
   Phase 4에서 `BoardRequest`에 `categoryCd` 필수 검증을 붙이면 그 메시지가 그대로 사용자에게
   보인다 — 한글로 쓸 것.

4. **PATCH 계열 컨트롤러에 `@Valid`가 빠져 있는 곳이 더 있을 수 있다.** 프로젝트 수정에서 발견했고
   다른 도메인은 확인하지 않았다. Phase 4에서 게시글 수정 API를 손댈 때 확인할 것.

5. **`next build`는 dev 서버와 동시에 돌리면 heap OOM으로 죽는다.**
   dev를 내리고 `NODE_OPTIONS=--max-old-space-size=6144 npm run build`.
   빌드가 `.next`를 덮어쓰므로 **빌드 후에는 반드시 `dev:clean`**.
