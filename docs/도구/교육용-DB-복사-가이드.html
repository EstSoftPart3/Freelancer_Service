옵션 요약
--src 이름 복사할 원본 스키마 · --dst 이름 만들 사본 스키마 · --apply 실제 실행(없으면 조사만) · --drop 사본이 이미 있으면 지우고 다시 만듦
--src/--dst 를 생략하면 예전 동작(운영 → 개발 DB 복제)이 된다. 교육용 복사에서는 반드시 둘 다 적는다.

0준비

시작 메뉴 → 「PowerShell」(또는 「터미널」)을 연다. 관리자 권한은 필요 없다.

0-1. Python 과 pymysql 확인

보이는 줄의미
Python 3.13.3Python 3.x 이면 된다. 「명령을 찾을 수 없음」이 나오면 python.org 에서 설치(설치 화면의 Add python.exe to PATH 체크)

0-2. DB 비밀번호를 환경변수로 등록 (PC 당 한 번)

스크립트는 비밀번호를 코드에 적지 않고 FREELANCER_DB_PW 환경변수에서 읽는다. 비밀번호 실제 값은 docs/시크릿.md(저장소에 올라가지 않는 파일) 또는 담당자에게 받는다.

칸넣을 값
첫 번째 'FREELANCER_DB_PW'변수 이름. 그대로 둔다
두 번째 '********'실제 DB 비밀번호. 작은따옴표는 남긴다
세 번째 'User'저장 범위(현재 Windows 사용자에게 영구 저장). 그대로 둔다
등록 후 PowerShell 창을 닫고 새로 연다. 이미 열려 있던 창은 새 환경변수를 모른다. 두 번째 명령이 True 면 등록된 것이다. 이 명령은 Git Bash 가 아니라 PowerShell 에서만 동작한다.

1조사 — 아무것도 바꾸지 않는다

저장소 폴더로 이동한 뒤 --apply 없이 실행한다. 접속·원본·대상을 확인만 하고 끝난다.

보이는 줄의미 · 확인할 것
서버접속한 DB 서버와 버전. 여기까지 나오면 비밀번호·네트워크는 정상
원본 … (읽기 전용)복사할 스키마. freelancer_education 인지 확인
대상만들어질 사본 이름. 끝 6자리가 이번 교육 시작일인지, 이전 기수 이름과 겹치지 않는지 확인
모드 : 조사만--apply 가 없으므로 DB 를 바꾸지 않는다
원본 구성테이블·뷰·트리거 수와 용량. 교육용은 테이블 58개 · 뷰/트리거 0개
문자셋사본도 같은 문자셋(utf8mb4)으로 만들어진다
대상 스키마가 이미 있으면 이 단계에서 ⚠ 대상 … 가 이미 있다 가 함께 나온다 → 4단계 참고.

2실행 — 사본 만들기

1단계 명령 끝에 --apply 만 붙인다. 20~40초 걸리고, 테이블마다 한 줄씩 진행 상황이 찍힌다.

보이는 줄의미
CREATE DATABASE …사본 스키마를 원본과 같은 문자셋으로 만들었다
[ n/58] 테이블명 … 행테이블 구조(키·기본값·코멘트·외래키 포함)를 만들고 데이터를 복사했다. 0 행 은 원래 비어 있는 테이블(정상)
행 수 대조 ✓원본과 사본의 테이블별 행 수를 다시 세어 비교했다. 이 줄이 성공의 기준이다
완료 · n초총 소요 시간

3확인

  • 성공: 마지막에 ✓ 전체 58개 테이블 일치 (합계 6,446 행) 와 완료 가 보인다. 행 수는 교육용 데이터가 바뀌면 달라질 수 있다.
  • 실패: ✗ 테이블명: 원본 N vs 사본 M 줄과 「행 수가 어긋난다. 복제 실패로 간주한다.」가 나온다 → 4단계 --drop 으로 다시 만든다.
  • 중간에 빨간 Python 오류(Traceback)로 끝났다면 사본이 반쯤 만들어진 상태다 → 원인(「문제 해결」 표)을 해결하고 --apply --drop 으로 다시 만든다.

4다시 만들기 — 사본이 이미 있을 때

4-1. --apply 만 주면: 건드리지 않고 멈춘다

기존 사본을 실수로 덮어쓰지 않도록 --drop 이 없으면 여기서 끝난다. DB 는 바뀌지 않았다.

4-2. --apply --drop: 사본을 지우고 처음부터 다시 복사

보이는 줄의미
+ 기존 대상 DROP이번 실행은 사본을 지운 뒤 만든다는 표시
DROP DATABASE …_261012사본만 삭제. 그 사본에서 바꾼 내용은 모두 사라진다. 이후는 2단계와 같다
사본을 교육 중에 수정해 썼다면 --drop 전에 그 내용이 필요 없는지 확인한다. 이전 기수 사본(다른 날짜)에 --drop 을 주지 않도록 --dst 의 날짜를 다시 확인한다. 다른 이름이 필요하면 --dst 만 바꿔 새 사본을 하나 더 만들면 된다.

안전장치가 막는 경우

대상에 운영 DB 나 교육용 원본 이름을 넣으면 DB 에 접속하기도 전에 중단한다.

중단 메시지원인
DST 가 원본 스키마(…)다. 덮어쓸 수 없다.--dst 에 freelancer_project(운영) 또는 freelancer_education(교육용 원본)을 넣었다
SRC 와 DST 가 같다.--src 와 --dst 가 같은 이름이다
원본 스키마 … 가 없다.--src 이름 오타
