## 핵심 설계: 포트를 그대로 물려받는다

기존 컨테이너를 **정지**시키고 **같은 포트**로 새 컨테이너를 올린다.
그러면 **NPM·Cloudflare 설정을 한 줄도 바꾸지 않는다.**

| 포트 | 기존 (제거됨) | 신규 |
|---|---|---|
| 8081 | `freelancer-api-server` | `freelancer-api` (Spring, prod 프로파일) |
| 8082 | `freelancer-web-server` (Vue) | `freelancer-next` (Next.js SSR) |
| 8083 | `freelancer-admin-server` | `freelancer-bo` (React BO) |

- 배포 당일엔 기존 컨테이너를 **정지만** 했다. 2026-08-04 정리 시 **삭제**했고
  정의는 `~/freelancer/rollback/` 에 보관했다 → 롤백 = 새것 down + **정의 파일로 재생성**(3장)
- 기존 파일(`/DATA/freelancer_project/`)도 **건드리지 않는다** → 별도 백업이 필요 없다
- 배포 파일은 전부 `~/freelancer/`(estsoft 소유) → **sudo 가 전혀 필요 없다**
- 업로드 디렉터리만 기존 것을 공유한다(estsoft 소유라 쓰기 가능)


> 🔴 **`DOCKER_BUILDKIT=0` 이 필요하다.** compose 의 `build.network: estsoft` 를
> BuildKit 이 지원하지 않는다(`network mode "estsoft" not supported by buildkit`).
>
> 네트워크가 왜 필요하냐면 — `sitemap.xml`·`rss.xml` 은 `revalidate` 가 걸린
> **정적 프리렌더**라 **빌드 시점에 백엔드를 호출한다.** 네트워크가 없으면 조용히

| 증상 | 원인 | 조치 |
|---|---|---|
| **sitemap 이 8건뿐** | `API_INTERNAL_BASE_URL` 이 런타임 env 에 없음 | 3-2 참조 |

| BO 화면은 뜨는데 데이터 없음 | `VITE_API_BASE_URL` 없이 빌드 | 0-2 대로 재빌드 |
| 전 도메인 530 / `1033` | 터널 다운 **또는 회선 장애** | 먼저 `ping -c2 192.168.2.1`·`getent hosts cloudflare.com`. 실패면 랜선·공유기 문제이고 터널 재시작은 무의미 |
| 첨부 이미지 전부 깨짐 | 업로드 경로 또는 `FILE_ENCRYPT_KEY` 변경 | `UPLOAD_DIR` 확인, 키는 절대 바꾸지 말 것 |
| 시간이 9시간 어긋남 | 컨테이너 TZ | compose 의 `TZ: Asia/Seoul` 확인 |
| **CasaOS UI 에서만 앱이 "정지"로 보임** | compose 에 `x-casaos` 블록 없음 | 5장 참조 |

### 3-2. 🔴 `API_INTERNAL_BASE_URL` 은 빌드·런타임 **양쪽 다** 필요하다

가장 헷갈리는 부분이고 실제로 여기서 한 번 걸렸다. 쓰이는 곳이 다르다.

| 어디 | 언제 읽나 | 무엇이 깨지나 |
|---|---|---|
| **빌드 ARG** | `next build` 시점 | `next.config.ts` 의 `/api/*` rewrite destination + sitemap 프리렌더 |
| **런타임 env** | 요청마다 | `lib/fetchers.ts`·`lib/api.ts`·`app/page.tsx` 의 서버 분기 |

`NEXT_PUBLIC_` 접두사가 **없는** 변수는 번들에 인라인되지 않는다. 서버가 요청 시점에
`process.env` 를 읽으므로 컨테이너 `environment:` 에도 반드시 넣어야 한다.
빠뜨리면 `safeGet` 이 fallback(빈 배열)을 반환해 **에러 없이 조용히 빈 화면**이 된다.

확인:
```bash
docker exec freelancer-next node -e 'console.log(process.env.API_INTERNAL_BASE_URL)'
# undefined 면 compose 의 environment: 에 빠진 것이다
```

> 🔴 그리고 **공개 도메인을 넣으면 안 된다.** rewrite 가 자기 자신을 가리켜 무한 루프가 된다.
> 반드시 컨테이너 내부 주소(`http://freelancer-api:8081/api`).

## 5. CasaOS UI 에 앱을 제대로 띄우기 (2026-08-04 해결)

### 증상

컨테이너는 `Up (healthy)` 인데 **CasaOS 대시보드에서만** 정지처럼 보였고,
거기서 "시작"을 누르면 `port is already allocated` 로 실패했다.
**자기 자신이 이미 그 포트를 쓰고 있어서** 나는 오류다. 서비스 장애가 아니다.

### 원인

CasaOS(v0.4.15)는 앱 목록을 이렇게 만든다.

1. 도커 라벨 `com.docker.compose.project` 로 compose 프로젝트를 **발견**한다
   → 앱 디렉터리가 `/var/lib/casaos/apps` 아래일 필요는 **없다**(`monitoring` 이 `~/monitoring` 에 있다)
2. 라벨 `com.docker.compose.project.config_files` 경로의 **원본 compose 파일을 다시 읽는다**
3. 거기에 **`x-casaos` 최상위 블록이 있어야** 관리 대상 앱으로 승격한다

3번이 없으면 `status: unknown` 이 되고, UI 는 이것을 정지처럼 그린다.
우리 `deploy/docker-compose.yml` 에 그 블록이 없었던 것이 전부다.

### 조치

`deploy/docker-compose.yml` 맨 끝에 블록을 추가했다. `x-` 로 시작하는 키는
docker compose 가 무시하므로 **배포 동작에는 영향이 없다.**

```yaml
x-casaos:
  author: self
  category: self
  hostname: ""
  icon: ""
  index: /
  is_uncontrolled: false
  port_map: "8082"        # 타일 클릭 시 열리는 포트(FO)
  scheme: http
  title:
    custom: Freelancer (Next)
```

파일만 고치면 된다 — 컨테이너 재기동 불필요. CasaOS 가 요청마다 파일을 다시 읽는다.

### 구 앱 타일(`tender_hazel` / 제목 `freelancer-api-total`) 정리

구 스택이 정지 상태로 타일에 남아 있어 **새로 배포한 것이 죽은 것처럼 오해를 샀다.**
구 컨테이너 3개를 삭제하고 앱 정의를 `~/freelancer/rollback/` 으로 옮겨 타일을 없앴다.
구 컨테이너는 마운트가 전부 `/DATA/freelancer_project` **bind** 라 삭제로 사라진 데이터는 없다.

### 상태 확인 명령 (UI 없이)

CasaOS 앱 관리 API 는 내부 포트에서 **인증 없이** 열려 있다. 포트는 매번 바뀐다.

```bash
# 앱 관리 서비스 포트 찾기 (127.0.0.1 리스닝 포트를 훑는다)
for p in $(ss -ltn | grep 127.0.0.1 | sed 's/.*127.0.0.1://;s/ .*//'); do
  curl -s -m 2 "http://127.0.0.1:$p/v2/app_management/compose" | grep -q '"data"' && echo "PORT=$p"
done

# 앱별 상태
curl -s http://127.0.0.1:<PORT>/v2/app_management/compose | python3 -c "
import sys,json
for k,v in sorted(json.load(sys.stdin)['data'].items()):
    t=v['compose'].get('x-casaos',{}).get('title',{})
    print('%-24s %-10s (%s)' % (t.get('custom') or t.get('en_us') or k, v['status'], k))
"
```
