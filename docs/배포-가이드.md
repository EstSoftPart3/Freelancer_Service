# 배포 가이드 (단독 수행용)

> 작성 2026-08-03 · 대상: `job.estsw.co.kr`(FO) · `admin-job.estsw.co.kr`(BO) · 백엔드
> 서버 구조는 `docs/서버-인프라-현황.md` 를 먼저 볼 것.

이 문서는 **혼자서 처음부터 끝까지 배포할 수 있게** 쓴 것이다. 명령을 위에서 아래로 그대로 따라가면 된다.

---

## 배포 방식 요약

| 대상 | 방식 | 롤백 |
|---|---|---|
| **백엔드** | jar 파일 교체 + 새 컨테이너로 갈아타기 | 기존 컨테이너 다시 `start` |
| **BO** | 정적 파일 교체 (기존 nginx 컨테이너 그대로) | 백업 폴더 되돌리기 |
| **FO** | 새 컨테이너(Next.js SSR) + NPM 전환 | NPM 을 8082(구 Vue)로 되돌리기 |

**이미지를 굽는 건 FO 뿐이다.** 나머지는 파일 교체라 되돌리기가 쉽다.

---

## ⚠️ 시작 전에 알아야 할 것

**현재 라이브는 "구버전 백엔드(5월 4일) + 최신 스키마 DB" 조합이다.**
회원가입·글쓰기처럼 새 컬럼을 쓰는 기능은 이미 실패하고 있을 수 있다.

→ **롤백이 "정상 상태 복귀"가 아니다.** 되돌려도 같은 불일치로 돌아간다.
→ 배포 전에 라이브에서 **회원가입·게시글 작성이 실제로 되는지 확인해두면**, 배포 후 문제가
   새로 생긴 것인지 원래 깨져 있던 것인지 구분할 수 있다. 5분이면 되니 꼭 하고 시작할 것.

## 0. 사전 준비

```bash
ssh estsoft@192.168.2.104
```

외부에서는 SSH 가 막혀 있다. 원격 작업이 필요하면 `docs/원격관리-구축.md` 를 먼저 적용할 것.

### 0-2. 소스 준비 (로컬 PC)

```bash
cd C:/dev/Freelancer_Service
git checkout NextJs
git pull
```

### 0-3. 백업 — 이걸 건너뛰면 되돌릴 수 없다

서버에서:

```bash
STAMP=$(date +%Y%m%d-%H%M)
mkdir -p ~/backup/$STAMP && cd ~/backup/$STAMP

# ① 백엔드 jar
sudo cp /DATA/freelancer_project/backend/backend-0.0.1-SNAPSHOT.jar ./backend-jar.bak

# ② BO 정적 파일
sudo tar czf admin.tar.gz -C /DATA/freelancer_project/admin .

# ③ 구 Vue 정적 파일 (FO 롤백용)
sudo tar czf frontend-vue.tar.gz -C /DATA/freelancer_project/frontend .

# ④ 업로드 파일
sudo tar czf uploads.tar.gz -C /DATA/freelancer_project/uploads .

# ⑤ DB 덤프 — mariadb 가 같은 서버의 컨테이너다
docker exec mariadb sh -c 'mysqldump -u root -p"$MYSQL_ROOT_PASSWORD" \
  --single-transaction --routines --triggers freelancer_project' > freelancer_project.sql

# ⑥ 기존 컨테이너 정의 (되돌릴 때 참고)
docker inspect freelancer-api-server > api-server-inspect.json
docker inspect freelancer-web-server > web-server-inspect.json
docker inspect freelancer-admin-server > admin-server-inspect.json

ls -lh   # 파일이 다 생겼는지 눈으로 확인
```

⑤ 가 실패하면 `docker exec -it mariadb env | grep MYSQL` 로 변수명을 확인하거나,
비밀번호를 직접 넣어 실행한다. **DB 덤프 없이는 진행하지 말 것.**

### 0-4. NPM 현재 설정 기록

브라우저에서 `http://192.168.2.104:81` → Proxy Hosts →
`job.estsw.co.kr` 과 `admin-job.estsw.co.kr` 의 **Forward Hostname/IP 와 Port 를 메모**한다.
(롤백 시 이 값으로 되돌린다. 캡처해두면 확실하다.)

## 1. 백엔드 배포

### 1-1. jar 빌드 (로컬 PC)

```bash
cd C:/dev/Freelancer_Service/backend
./gradlew clean bootJar -x test
ls -lh build/libs/          # backend-0.0.1-SNAPSHOT.jar 생성 확인
```

서버에서 빌드하고 싶으면(로컬에 JDK 21 이 없을 때) 도커로 할 수 있다:

```bash
# 서버에서, 소스를 올린 뒤
docker run --rm -v $PWD:/w -w /w eclipse-temurin:21-jdk ./gradlew clean bootJar -x test
```

### 1-2. jar 업로드

로컬 PC 에서:

```bash
scp C:/dev/Freelancer_Service/backend/build/libs/backend-0.0.1-SNAPSHOT.jar \
    estsoft@192.168.2.104:/tmp/backend-new.jar
```

서버에서:

```bash
sudo cp /tmp/backend-new.jar /DATA/freelancer_project/backend/backend-0.0.1-SNAPSHOT.jar
ls -lh /DATA/freelancer_project/backend/    # 날짜가 오늘로 바뀌었는지 확인
```

### 1-3. 배포 구성 올리기

로컬 PC 에서:

```bash
scp -r C:/dev/Freelancer_Service/deploy estsoft@192.168.2.104:/tmp/deploy
```

서버에서:

```bash
mkdir -p ~/freelancer-deploy && cp -r /tmp/deploy/* ~/freelancer-deploy/
cd ~/freelancer-deploy
cp .env.example .env
vi .env      # 값 채우기 — 로컬 backend/src/main/resources/application.yml 에서 그대로 옮긴다
```

`.env` 에서 **반드시 채워야 하는 것**: `DB_USERNAME`·`DB_PASSWORD`·`REDIS_PASSWORD`·`JWT_SECRET`·
`MAIL_USERNAME`·`MAIL_PASSWORD`·`AWS_ACCESS_KEY`·`AWS_SECRET_KEY`·`AWS_S3_BUCKET`·
`BUSINESS_VERIFY_API_KEY`·`FILE_ENCRYPT_KEY`·`NAVER_MAP_CLIENT_ID`·`NAVER_MAP_CLIENT_SECRET`·
`ADMIN_MASTER_PASSWORD`

하나라도 빠지면 **기동이 실패한다**(의도한 설계다 — 잘못된 값으로 조용히 도는 것보다 낫다).

### 1-4. 네트워크 확인

새 백엔드가 `redis`·`mariadb` 를 컨테이너명으로 찾는다. 같은 네트워크에 있어야 한다.

```bash
docker network inspect freelancer-admin --format '{{range .Containers}}{{.Name}} {{end}}'
```

`redis` 나 `mariadb` 가 목록에 없으면 붙인다:

```bash
docker network connect freelancer-admin redis
docker network connect freelancer-admin mariadb
```

> `mariadb` 를 붙이기 싫으면 `.env` 의 `DB_URL` 호스트를 `db.estsw.co.kr` 로 두면 된다
> (외부 도메인을 한 바퀴 도는 대신 네트워크 설정을 안 건드려도 된다).

### 1-5. 기존 백엔드 정지 → 새 백엔드 기동

```bash
cd ~/freelancer-deploy

# 기존 컨테이너는 **정지만** 한다(지우지 않는다 — 롤백 수단이다)
docker stop freelancer-api-server

docker compose up -d backend
docker compose ps
docker compose logs -f backend      # Ctrl+C 로 빠져나온다
```

로그에서 확인할 것:
- `The following 1 profile is active: "prod"` ← **이게 안 보이면 Security 가 안 걸린 것이다. 중단할 것**
- `Tomcat started on port 8081`
- 예외 스택 없이 `Started DemoApplication`

### 1-6. 백엔드 검증

```bash
curl -s http://localhost:8081/api/actuator/health          # {"status":"UP"} (details 는 안 나오는 게 정상)
curl -s -o /dev/null -w "%{http_code}\n" "http://localhost:8081/api/board?page=1&size=5&sortType=latest"   # 200
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8081/api/me                                       # 401 (토큰 없으니 정상)
```

`/api/me` 가 **401 이 아니라 200 이나 basic auth 창**이면 prod 프로파일이 안 걸린 것이다 → 1-5 로 돌아갈 것.

## 2. BO 배포 (정적 파일 교체)

### 2-1. 빌드 (로컬 PC)

BO 는 API 주소가 **빌드 타임에 박힌다.** 반드시 환경변수를 주고 빌드한다.

```bash
cd C:/dev/Freelancer_Service/frontend/react_js

# PowerShell
$env:VITE_API_BASE_URL="https://job.estsw.co.kr/api"; npm run build

# Git Bash
VITE_API_BASE_URL=https://job.estsw.co.kr/api npm run build

ls dist/    # index.html, assets/, images/ 생성 확인
```

> `admin-job` 에서 `job` 도메인의 API 를 부르므로 CORS 가 발생하지만,
> `SecurityConfigProd` 에 `https://admin-job.estsw.co.kr` 이 이미 허용돼 있어 통과한다.

### 2-2. 업로드

로컬 PC 에서:

```bash
cd C:/dev/Freelancer_Service/frontend/react_js
tar czf bo-dist.tar.gz -C dist .
scp bo-dist.tar.gz estsoft@192.168.2.104:/tmp/
```

서버에서:

```bash
# 기존 파일 치우기 — default.conf 와 uploads 는 남겨야 한다
cd /DATA/freelancer_project/admin
sudo mkdir -p /tmp/admin-old && sudo mv assets images index.html /tmp/admin-old/ 2>/dev/null

# 새 파일 풀기
sudo tar xzf /tmp/bo-dist.tar.gz -C /DATA/freelancer_project/admin
```

정적 파일이라 **컨테이너 재시작이 필요 없다.**

### 2-3. 검증

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8083/     # 200
```

브라우저에서 `https://admin-job.estsw.co.kr` → 관리자 로그인 → **사이드바에 소속 관리·프로젝트 관리·
커뮤니티 시드가 보이는지** 확인(이게 보이면 최신 BO 가 올라간 것이다).

## 3. FO 배포 (Next.js — 신규 컨테이너)

### 3-1. 소스 업로드

로컬 PC 에서:

```bash
cd C:/dev/Freelancer_Service
tar czf fo-src.tar.gz --exclude=node_modules --exclude=.next -C frontend/nextjs .
scp fo-src.tar.gz estsoft@192.168.2.104:/tmp/
```

서버에서:

```bash
mkdir -p ~/freelancer-src/nextjs && tar xzf /tmp/fo-src.tar.gz -C ~/freelancer-src/nextjs
```

`deploy/docker-compose.yml` 의 빌드 컨텍스트가 `../frontend/nextjs` 이므로 경로를 맞춘다:

```bash
mkdir -p ~/freelancer/frontend
mv ~/freelancer-src/nextjs ~/freelancer/frontend/nextjs
cp -r ~/freelancer-deploy ~/freelancer/deploy
cd ~/freelancer/deploy
```

### 3-2. 이미지 빌드 + 기동

```bash
docker compose build frontend-next     # 5~10분 걸린다
docker compose up -d frontend-next
docker compose ps
docker logs -f freelancer-next
```

`▲ Next.js 16.x` 와 `Ready in ...` 가 뜨면 정상이다.

### 3-3. 컨테이너 단독 검증 (도메인 전환 전)

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8084/                 # 200
curl -s http://localhost:8084/ | head -c 300                                     # HTML 이 나오는지
curl -s -o /dev/null -w "%{http_code}\n" "http://localhost:8084/api/board?page=1&size=5&sortType=latest"  # 200
```

세 번째가 **중요하다** — Next 의 `/api/*` rewrite 가 백엔드에 제대로 닿는지 보는 것이다.
여기서 502·504 가 나오면 `API_INTERNAL_BASE_URL` 이 잘못됐거나 네트워크가 안 붙은 것이다.

### 3-4. 도메인 전환 (NPM)

브라우저 `http://192.168.2.104:81` → **Proxy Hosts** → `job.estsw.co.kr` 편집

- **Forward Port** 를 `8082` → **`8084`** 로 변경
- `/api` 용 커스텀 location 이 따로 있으면 **삭제한다** (Next 가 자체 rewrite 로 백엔드에 넘긴다)
- Save

> ⚠️ `/api` location 을 남겨두면 Next rewrite 와 이중으로 걸려 예측하기 어려운 동작이 된다.
> 잘 모르겠으면 남겨둬도 동작은 하지만(NPM 이 먼저 잡음), 전환 후 3-6 검증을 꼭 할 것.

### 3-5. 🔴 Cloudflare 캐시 purge

**이걸 빠뜨리면 배포가 안 된 것처럼 보인다.** 구 Vue 정적 파일이 엣지에 남아 계속 서빙된다.

Cloudflare 대시보드 → `estsw.co.kr` → Caching → Configuration → **Purge Everything**

### 3-6. 최종 검증

```bash
curl -s -o /dev/null -w "FO=%{http_code}\n" https://job.estsw.co.kr/
curl -s -o /dev/null -w "API=%{http_code}\n" "https://job.estsw.co.kr/api/board?page=1&size=5&sortType=latest"
curl -s -o /dev/null -w "BO=%{http_code}\n" https://admin-job.estsw.co.kr/
curl -s https://job.estsw.co.kr/sitemap.xml | head -c 300
curl -s https://job.estsw.co.kr/robots.txt
```

브라우저(시크릿 창)에서:

- [ ] `https://job.estsw.co.kr` 첫 화면이 **Next.js 버전**인지 (구 Vue 와 디자인이 다르다)
- [ ] 프로젝트 목록·상세 열림
- [ ] **로그인** 되는지
- [ ] 게시글 작성 → 파일 첨부 → 업로드된 이미지가 보이는지
- [ ] 페이지 소스에 `<title>`·JSON-LD 가 박혀 있는지 (SSR 확인)
- [ ] 개발자도구 콘솔에 CORS 에러가 없는지
- [ ] `https://admin-job.estsw.co.kr` 관리자 로그인 → 게시물·소속·프로젝트 관리 동작

전체 항목은 `docs/seo-deployment-guide.md` 5절 참조.

## 4. 롤백

### 4-1. FO 만 되돌리기 (가장 흔한 경우)

NPM 에서 `job.estsw.co.kr` 의 Forward Port 를 **8084 → 8082** 로 되돌린다.
→ 구 Vue 가 즉시 다시 서빙된다. **Cloudflare Purge Everything 을 다시 한 번.**

### 4-2. 백엔드 되돌리기

```bash
cd ~/freelancer-deploy
docker compose stop backend

# jar 복구
sudo cp ~/backup/<STAMP>/backend-jar.bak /DATA/freelancer_project/backend/backend-0.0.1-SNAPSHOT.jar

# 기존 컨테이너 재기동
docker start freelancer-api-server
curl -s http://localhost:8081/api/actuator/health
```

### 4-3. BO 되돌리기

```bash
cd /DATA/freelancer_project/admin
sudo rm -rf assets images index.html
sudo tar xzf ~/backup/<STAMP>/admin.tar.gz -C /DATA/freelancer_project/admin
```

### 4-4. 전부 되돌리기

```bash
cd ~/freelancer-deploy && docker compose down
docker start freelancer-api-server freelancer-web-server freelancer-admin-server
# NPM: job → 8082, admin-job → 8083 으로 복구
# Cloudflare Purge Everything
```

## 5. 자주 겪는 문제

| 증상 | 원인 | 조치 |
|---|---|---|
| 배포했는데 화면이 그대로 | Cloudflare 캐시 | Purge Everything |
| 전 도메인이 동시에 530 / `error code 1033` | 터널 다운. **회선 장애일 때도 증상이 같다** | 먼저 `ping -c2 192.168.2.1` 과 `getent hosts cloudflare.com` — 여기서 실패하면 랜선·공유기 문제이고 터널 재시작은 무의미하다. 둘 다 정상이면 `docker restart cloudflared-tunnel` |
| FO 는 뜨는데 API 만 502/504 | `API_INTERNAL_BASE_URL` 오류 또는 네트워크 미연결 | `docker network inspect freelancer-admin` 로 백엔드가 붙어 있는지 확인 |
| **FO 요청이 무한 루프 / 타임아웃** | `API_INTERNAL_BASE_URL` 에 공개 도메인을 넣음 | 반드시 컨테이너 내부 주소(`http://freelancer-api:8081/api`) |
| 백엔드가 basic auth 창을 띄움 | `SPRING_PROFILES_ACTIVE=prod` 누락 | 로그에서 `profile is active: "prod"` 확인 |
| 백엔드 기동 실패, `Could not resolve placeholder` | `.env` 값 누락 | 오류 메시지의 변수명을 `.env` 에 채운다 |
| 첨부 이미지가 전부 깨짐 | 업로드 볼륨 경로 오류 또는 `FILE_ENCRYPT_KEY` 변경 | `UPLOAD_DIR` 확인, 키는 절대 바꾸지 말 것 |
| 게시글 저장 시 500 | 구버전 jar + 신 스키마 | 백엔드 배포가 실제로 됐는지 jar 날짜 확인 |
| BO 화면은 뜨는데 데이터가 안 나옴 | `VITE_API_BASE_URL` 없이 빌드 | 2-1 대로 환경변수를 주고 재빌드 |
| 시간이 9시간 어긋남 | 컨테이너 TZ | compose 의 `TZ: Asia/Seoul` 확인 |

### 로그 보는 법

```bash
docker logs --tail 200 freelancer-api      # 백엔드
docker logs --tail 200 freelancer-next     # FO
docker logs --tail 100 cloudflared-tunnel  # 터널
```

웹으로도 볼 수 있다 — `log.estsw.co.kr` (Dozzle).
