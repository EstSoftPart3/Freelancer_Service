## 이 문서를 쓰는 법

### 🔴 제목을 그대로 베끼지 않는다

여기 있는 것은 **소재**이지 제목이 아니다. 그대로 올리면 게시판이 CS 문제집처럼 보이고,
"이 사람이 실제로 겪은 일"이라는 느낌이 사라진다. **자기 상황을 앞에 붙여 다시 쓴다.**

| 은행 소재 | 실제로 올릴 제목 |
|---|---|
| A041 N+1 문제 | 공고 목록에서 모집인원까지 같이 뽑으니 쿼리가 51번 나갑니다 |
| A067 CORS | 로컬 3000 → 8080 호출은 되는데 배포하니 CORS 로 막힙니다 |
| A215 서버 컴포넌트 | Next.js App Router 에서 useState 쓰려니 오류가 납니다 |

본문에는 공지의 3요소(**상황 / 시도 / 막힌 지점**)를 넣는다.
**이미 아는 내용이라도 "왜 헷갈렸는지"를 쓰면 그게 곧 남의 30분을 아껴주는 글이 된다.**

### 중복 방지

- 스프레드시트에 `번호 / 쓴 사람 / 날짜 / 글 주소` 를 남기고 **쓴 번호는 소진 처리**한다.
- 같은 번호를 다른 사람이 다시 쓰는 것은 **관점이 다르면 허용**한다
  (예: 같은 N+1 이라도 JPA 관점 / MyBatis 관점). 단 본문이 겹치면 안 된다.

### 배분 기준

하루 10명이 서로 다른 영역에서 고르도록 **같은 날 같은 대분류는 3명까지**로 제한한다.
전원이 같은 날 Spring 만 쓰면 목록이 한 색이 된다.
