## 5. 🔴 라이브 버전 불일치 — 배포 전 반드시 알아야 할 것

| 대상 | 라이브 빌드 | 상태 |
|---|---|---|
| 백엔드 jar | **2026-05-04** | Phase 0~8 백엔드 변경이 **하나도 반영되지 않음** |
| BO (admin) | **2026-03-31** | 소속·프로젝트 관리, 커뮤니티 시드, 권한 강화 전부 없음 |
| FO (Vue) | 2026-04-20 | Next.js 로 교체 대상 |
| **DB** | **최신** | Phase 1~4 스키마 반영 완료(닉네임 NOT NULL·카테고리 필수·VOC 컬럼) |

**즉 현재 라이브는 "구버전 백엔드 + 신 스키마 DB" 조합이다.**
새 컬럼을 요구하는 경로(회원가입의 닉네임, 게시글의 카테고리 등)는 이미 실패하고 있을 가능성이 높다.

이것이 배포 계획에 주는 영향:

- **"구버전으로 롤백"이 안전지대가 아니다.** 롤백해도 DB 는 그대로라 같은 불일치로 돌아간다.
  롤백은 "정상 상태 복귀"가 아니라 "새 문제 회피"일 뿐이다.
- 그러므로 **백엔드를 먼저 최신으로 올리는 것**이 오히려 위험을 줄인다.
- 배포 전에 라이브에서 회원가입·글쓰기가 실제로 되는지 확인해두면, 배포 후 문제가 새로 생긴 것인지
  원래 깨져 있던 것인지 구분할 수 있다.

## 6. 외부 접근 제약 · 장애 이력

- **외부에서 SSH 불가** — `estsw.co.kr`·`casa.estsw.co.kr`·`job.estsw.co.kr` 전부 22번 포트가 닫혀 있다.
  Cloudflare 프록시는 HTTP/HTTPS 만 통과시킨다.
- **모든 웹 서비스가 Cloudflare Tunnel 하나에 물려 있다.** 터널이 끊기면 전 도메인이 동시에 죽고,
  `casa.estsw.co.kr`(CasaOS UI)도 함께 죽어 **원격 복구 수단이 사라진다.**
- **DNS 서버가 공유기(`192.168.2.1`) 하나뿐이고 폴백이 없다** — 단일 장애점.

### 🔴 2026-08-03 장애 (22.5시간) — 원인 확정

**서버 PC 의 랜선이 물리적으로 빠져 있었다.** 랜선 분리 → 게이트웨이 도달 불가 → DNS 실패 →
cloudflared 가 `argotunnel.com` SRV 조회에 실패해 자체 종료 → 재시작 반복 → 전 도메인 530(1033).

- 구간: 08-03 10:39 ~ 08-04 09:08. 서버 재부팅 없음(uptime 175일 유지)
- **복구는 자동이었다** — 케이블 재연결 후 09:08:38 에 터널이 스스로 4개 연결 등록
- 재시작 정책은 **원래 전부 설정돼 있었다**(`always`/`unless-stopped`, 13개 전부)
- 텔레그램 봇도 죽지 않았다 — 인터넷이 끊겨 발송만 실패, 알림 84건이 `undelivered_alerts.log` 에 적재
- **아무도 22시간 동안 몰랐던 이유**: 감시 시스템이 전부 서버 안에 있다.
  끊긴 네트워크 안의 감시는 자기 네트워크가 끊겼다는 걸 알릴 수 없다 → **외부 감시 필요**

**고친 것**: watchdog 이 회선 장애를 터널 장애로 오판해 85회 무의미하게 재시작했다.
`uplink_ok()` 를 추가해 터널/NPM 판정 **전에** 게이트웨이·공인망·DNS 를 먼저 확인하게 했다(08-04 적용).

→ 상세와 남은 보완안(외부 감시·DNS 폴백·Tailscale)은 **`docs/원격관리-구축.md`** 참조.

## 7. 자주 쓸 조사 명령

```bash
# 전체 컨테이너 상태
docker ps -a --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}'

# 특정 컨테이너 볼륨/네트워크
docker inspect freelancer-api-server --format '{{range .Mounts}}{{.Source}} => {{.Destination}}{{println}}{{end}}'
docker inspect freelancer-api-server --format '{{range $k,$v := .NetworkSettings.Networks}}{{$k}} {{end}}'

# 백엔드 로그 (마지막 100줄)
docker logs --tail 100 freelancer-api-server

# 헬스체크
curl -s http://localhost:8081/api/actuator/health

# NPM 프록시 설정 전체
docker exec nginxproxymanager sh -c 'cat /data/nginx/proxy_host/*.conf'

# 터널 상태
docker logs --tail 50 cloudflared-tunnel

# 감시 시스템이 이미 판단해둔 것 (장애 조사 시 여기부터)
tail -30 ~/monitoring/events.log
tail -40 ~/monitoring/undelivered_alerts.log   # 못 보낸 알림 = 네트워크 장애 이력
ls -t ~/monitoring/incidents | head -5

# 업링크 확인 (장애 시 물리 계층부터)
ip link show ; ping -c 2 192.168.2.1 ; getent hosts cloudflare.com
```
