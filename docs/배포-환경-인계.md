## 1. 접속 정보 총람

### 1-1. 서버 SSH

```bash
ssh  -i ~/.ssh/id_ed25519_casaos estsoft@192.168.2.104
scp  -i ~/.ssh/id_ed25519_casaos <파일> estsoft@192.168.2.104:<경로>
```

- 🔴 **`-i` 로 키를 명시해야 붙는다.** 그냥 `ssh estsoft@192.168.2.104` 는
  `Permission denied (publickey,password)` 가 난다.
- 🔴 **내부망 전용.** 외부에서는 22번이 닫혀 있고 Cloudflare 는 HTTP/HTTPS 만 통과시킨다.
  → 사무실 밖에서는 서버에 들어갈 방법이 **없다** ([12-2](#12-미조치다음-사람-몫) Tailscale).
- 계정 `estsoft` 는 **docker 그룹 소속**이라 sudo 없이 도커를 다 조작한다.
  배포 파일이 전부 `~/freelancer/`(estsoft 소유)라 **배포에 sudo 가 전혀 필요 없다.**
- `sudo` 는 비밀번호가 필요하다 → ⬜ **비밀번호 미확인 (사용자 확인 필요)**
- 🔴 **키는 이 PC 의 `~/.ssh/id_ed25519_casaos` 에만 있다.** 다른 PC 로 옮기려면
  개인키 파일을 복사하거나(`chmod 600` 필수), **지금 접속이 살아 있을 때** 새 공개키를
  서버 `~/.ssh/authorized_keys` 에 추가해 둬야 한다. 접속이 끊긴 뒤에는 방법이 없다
  (외부 SSH 불가 + 콘솔 물리 접근 필요).

`~/freelancer/deploy/.env` 하나가 compose 를 통해 컨테이너로 들어간다.
🔴 **빠뜨리면 기동이 실패한다** — `application-prod.yml` 의 `${VAR}` 에 기본값을 일부러 안 뒀다.

| 키 | 현재 값 | 읽는 시점 | 빠지거나 틀리면 |
|---|---|---|---|
| `SPRING_PROFILES_ACTIVE` | `prod` (compose 에 하드코딩) | 백엔드 기동 | 🔴 `SecurityConfigDev/Prod` 둘 다 `@Profile` 이라 **Security 가 통째로 비활성** → 전 경로 basic auth 창 |
| **`API_INTERNAL_BASE_URL`** | `http://freelancer-api:8081/api` | **빌드 ARG + 런타임 env 양쪽** | 🔴 아래 별도 설명 |
| `FO_PUBLIC_URL` | `https://job.estsw.co.kr` | 빌드 ARG (`NEXT_PUBLIC_SITE_URL`) | canonical·sitemap·OG URL 이 엉뚱한 도메인 |
| `BO_PUBLIC_URL` | `https://admin-job.estsw.co.kr` | 백엔드 런타임 (`BO_BASE_URL`) | 메일 안의 BO 링크가 깨짐 |
| `UPLOAD_DIR` | `/DATA/freelancer_project/uploads` | 볼륨 마운트 | 🔴 다른 경로면 **기존 첨부가 전부 깨진다** |
| `FILE_ENCRYPT_KEY` | (§1-4) | 백엔드 런타임 | 🔴 바꾸면 **이미 올라간 첨부를 복호화 못 한다** |
| `DB_URL`·`DB_USERNAME`·`DB_PASSWORD` | `mariadb:3306/freelancer_project` | 기동 | `Could not resolve placeholder` 로 기동 실패 |
| `REDIS_*` | `redis:6379` / `{{REDIS_PW}}` | 기동 | 세션·캐시 실패 |
| `JWT_SECRET` | (§1-4) | 런타임 | 🔴 바꾸면 **발급된 토큰이 전부 무효** → 전원 강제 로그아웃 |
| `MAIL_*` | Gmail 앱 비밀번호 | 런타임 | 이메일 인증·VOC 알림 미발송 |
| `AWS_*` | S3 | 런타임 | S3 경로 업로드 실패 |
| `BUSINESS_VERIFY_API_KEY` | 국세청 | 런타임 | 사업자 인증 실패 |
| `NAVER_MAP_*` | 지도 | 런타임 | 근무지 지도 미표시 |

| `IMAGE_TAG` | `latest` | 이미지 태그 | 롤백용으로 버전을 박고 싶을 때 쓴다 |
| `BACKEND_PORT`·`*_HOST_PORT` | 8081·8082·8083 | 포트 매핑 | 🔴 바꾸면 **NPM 설정도 같이 고쳐야 한다** |

### 🔴 `API_INTERNAL_BASE_URL` — 가장 자주 걸리는 함정

**빌드 타임과 런타임 양쪽에 다 필요하고, 쓰이는 곳이 다르다.**

| 어디 | 언제 읽나 | 없으면 깨지는 것 |
|---|---|---|
| 빌드 ARG | `next build` | `next.config.ts` 의 `/api/*` rewrite destination + **sitemap·rss 프리렌더** |
| 런타임 env | 요청마다 | `lib/fetchers.ts`·`lib/api.ts`·`app/page.tsx` 의 서버 분기 |

`NEXT_PUBLIC_` 이 **없는** 변수는 번들에 인라인되지 않는다 → 서버가 요청 시점에 `process.env` 를 읽는다.
런타임 쪽을 빠뜨리면 `safeGet` 이 fallback(빈 배열)을 반환해 **에러 없이 조용히 빈 화면**이 된다.

```bash
docker exec freelancer-next node -e 'console.log(process.env.API_INTERNAL_BASE_URL)'
# undefined 면 compose 의 environment: 에서 빠진 것
```

🔴 **공개 도메인을 넣으면 안 된다.** rewrite 가 자기 자신을 가리켜 무한 루프가 된다.
반드시 컨테이너 내부 주소 `http://freelancer-api:8081/api`.

### CORS 는 코드에 하드코딩돼 있다

`SecurityConfigProd.corsConfigurationSource()` 에 `https://job.estsw.co.kr`·`https://admin-job.estsw.co.kr`
두 개가 박혀 있다. **도메인이 바뀌면 이 빈을 고쳐 백엔드를 재빌드해야 한다.**

## 10. DB 운영

### 10-1. 대전제 — 개발 DB 와 운영 DB 는 분리돼 있다 (2026-09-01~)

| | 스키마 | 누가 보는가 |
|---|---|---|
| 개발 | `freelancer_develop` | 로컬 `bootRun`, `docs/도구/*.py` 기본값 |
| 운영 | `freelancer_project` | 실서버 `freelancer-api` 컨테이너 |

**같은 서버(`db.estsw.co.kr`)에 이름만 다른 두 스키마**다. 호스트가 같으니 안전장치는
스키마 이름 하나뿐이다. `dbconfig.py` 가 그 안전장치 역할을 한다 — **기본이 개발이고,
운영을 건드리려면 `--prod` 를 명시**해야 한다.

**개발 DB 는 언제든 버려도 되는 사본**이다. 꼬였으면 고치지 말고 다시 뜬다:

```bash
!python "C:/dev/Freelancer_Service/docs/도구/db-clone-develop.py"                 # 조사만
!python "C:/dev/Freelancer_Service/docs/도구/db-clone-develop.py" --apply --drop  # 운영에서 다시 복제
```

운영을 대상으로 하는 작업은 예전 그대로 **드라이런 → 눈으로 확인 → `--apply`**, 백업이 먼저다.

### 10-2. 🔴 배포 전 DB 반영 절차

스키마 변경은 개발 DB 에서 운영 DB 로 **자동으로 넘어가지 않는다.** 배포 순서는 항상:

```
① 개발 DB 에서 변경·검증
② 운영 DB 에 같은 변경 적용     ← 이 단계를 빠뜨리면 배포 직후 500 이 난다
③ 애플리케이션 배포
```

②를 빠뜨렸는지 확인하는 도구가 `db-diff-schema.py` 다. **배포 직전에 반드시 한 번 돌린다.**

```bash
# 1) 운영에 아직 안 넘어간 구조 변경이 있는지 (읽기 전용)
!python "C:/dev/Freelancer_Service/docs/도구/db-diff-schema.py" --sql

# 2) 차이가 있으면 — 백업 먼저
!python "C:/dev/Freelancer_Service/docs/도구/db-backup.py"

# 3) 마이그레이션 스크립트를 운영에 적용 (--prod 없으면 개발 DB 에 적용된다)
!python "C:/dev/Freelancer_Service/docs/도구/migrate-<이름>.py" --prod           # 드라이런
!python "C:/dev/Freelancer_Service/docs/도구/migrate-<이름>.py" --prod --apply

# 4) 다시 차이 확인 → "구조 차이 없음" 이어야 배포한다
!python "C:/dev/Freelancer_Service/docs/도구/db-diff-schema.py"
```

`--sql` 이 뱉는 DDL 은 **제안**이다. 그대로 돌리기 전에 눈으로 볼 것. 데이터 이관이 필요한
변경(컬럼 분해·값 재계산 등)은 DDL 만으로 끝나지 않으므로 마이그레이션 스크립트를 쓴다.

**DB 변경이 있는 기능은 백엔드·DB 배포 순서도 중요하다.** 컬럼 추가처럼 하위호환이면
DB 먼저가 안전하고, 컬럼 삭제·이름변경이면 구버전 백엔드가 죽으므로 무중단이 불가능하다.

  → **백엔드를 먼저 띄운 뒤 FO 를 빌드**해야 한다.

### 파일 교체

- 🔴 **실행 중인 JVM 이 물고 있는 jar 을 scp 로 제자리 덮어쓰면 안 된다.**
  `.new` 로 올린 뒤 서버에서 **rename 으로 교체**한다(스크립트가 처리).
- 🔴 **FO 소스는 덮어쓰지 말고 디렉터리째 갈아끼운다.** 구버전의 `app/icon.tsx`·`apple-icon.tsx`·
  `opengraph-image.tsx` 가 남아 있으면 새 `icon.png` 계열과 **메타데이터 라우트가 충돌**한다.
  스크립트가 `.tsx` 잔존 검사를 하고 남아 있으면 중단한다.
- 🔴 **`~/freelancer/admin/uploads` 디렉터리가 미리 있어야 한다.** BO 는 `admin` 을 읽기전용으로
  마운트한 뒤 그 안에 uploads 를 겹쳐 마운트한다. 없으면 마운트 지점을 만들 수 없어
  `read-only file system` 으로 기동 실패한다.
- BO 정적파일 교체 시 **`uploads` 는 지우면 안 된다**(마운트 지점). 스크립트가 `! -name uploads` 로 제외한다.

### 설정

- 🔴 **`SPRING_PROFILES_ACTIVE=prod` 가 없으면 Security 가 아예 비활성이다.**
  `SecurityConfigDev`·`SecurityConfigProd` 둘 다 `@Profile` 이라 어느 쪽도 안 걸린다.
  기동 로그에 `The following 1 profile is active: "prod"` 가 **반드시** 보여야 한다.
- 🔴 **`API_INTERNAL_BASE_URL` 은 빌드·런타임 양쪽 다** ([5절](#-api_internal_base_url--가장-자주-걸리는-함정)).
- 🔴 **`FILE_ENCRYPT_KEY`·`JWT_SECRET` 은 바꾸지 말 것** (첨부 복호화 불가 / 전원 강제 로그아웃).
- 컨테이너 `TZ` 는 **KST 고정**. UTC 면 모집 마감 판정이 9시간 어긋난다.
- **CORS 는 코드 하드코딩**(`SecurityConfigProd`). 도메인이 바뀌면 백엔드를 재빌드해야 한다.

### CasaOS

- 🔴 **`docker-compose.yml` 끝의 `x-casaos` 블록을 지우면 UI 에서만 앱이 "정지"로 보인다.**
  CasaOS 는 라벨로 compose 프로젝트를 발견한 뒤 `config_files` 경로의 **원본 파일을 다시 읽어**
  이 블록이 있어야 관리 대상 앱으로 승격시킨다. 없으면 `status: unknown` 이 되고 UI 가 정지처럼 그린다.
  거기서 "시작"을 누르면 **자기가 이미 쓰는 포트라** `port is already allocated` 로 실패한다.
  `x-` 로 시작하는 키는 docker compose 가 무시하므로 **배포 동작에는 영향이 없다.**
  파일만 고치면 되고 재기동도 필요 없다(CasaOS 가 요청마다 다시 읽는다).

### 그 밖

- `/api/files/<uuid>` 는 **확장자까지 있어야 200 이다** — 경로 변수는 `savedName` 전체다.
- Cloudflare 캐시 purge 는 대개 불필요하다(HTML 이 `cf-cache-status: DYNAMIC`).
- 실행 중인 `cloudflared` 는 **2026.3.0** 이고 기동 로그가 매일 구버전 경고를 남긴다(동작에는 지장 없음).

### 12-1. 외부 감시 (최우선)

계정 만들고 URL 하나 등록하면 끝난다. 무료 요금제로 충분하다.

1. https://uptimerobot.com 가입 (무료 50개 모니터)
2. Monitor Type `HTTPS` · URL `https://job.estsw.co.kr` · 간격 5분
3. Alert Contact 에 **이메일 + 휴대폰 앱 푸시** 등록
4. `https://admin-job.estsw.co.kr` 도 하나 더 (선택)

이러면 서버가 통째로 죽어도, 회선이 끊겨도 알림이 온다.

### 12-2. Tailscale (원격 접속 수단)

| 경로 | 가능? | 이유 |
|---|---|---|
| SSH `192.168.2.104` | ❌ | 내부망 전용 |
| SSH 공인 도메인 | ❌ | 22번 미노출, Cloudflare 는 HTTP/HTTPS 만 |
| CasaOS UI | ❌ | **같은 터널에 물려 있어 함께 죽는다** |

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up --ssh
tailscale ip -4        # 100.x.x.x
```
🔴 **반드시 다른 네트워크에서 접속을 검증할 것.** 사무실 안에서 확인하면 내부망으로 붙은 건지
Tailscale 로 붙은 건지 구분되지 않는다.
공유기 포트포워딩(22번 개방)은 권하지 않는다 — 자동화된 무차별 대입이 곧바로 들어온다.

### 12-3. DNS 다중화가 보류인 이유

`FallbackDNS=` 는 **동작하지 않는다.** DHCP 로 `192.168.2.1` 이 이미 잡혀 있으면 응답이 없어도
fallback 은 절대 쓰이지 않는다(`man resolved.conf`). 제대로 하려면 netplan 에서 링크의
nameservers 를 직접 지정하고 `dhcp4-overrides.use-dns: false` 를 줘야 하는데,
**원격에서 잘못 건드리면 내부망에서도 접속이 불가능해진다.** 물리적으로 접근할 수 있을 때 할 것.

그리고 이번 장애에는 애초에 도움이 되지 않았다 — 랜선이 빠지면 어떤 DNS 도 닿지 않는다.

### 12-4. 검색엔진 등록

`.env` 의 `NAVER_SITE_VERIFICATION`·`GA_ID` 가 비어 있다. 이 둘은 **빌드 ARG** 라
값을 채우면 **FO 이미지를 다시 구워야** 반영된다.

절차는 `docs/seo-deployment-guide.md` 3·4장 (네이버 서치어드바이저 / 구글 서치콘솔).
> ⚠️ 그 문서의 환경변수명 `NEXT_PUBLIC_API_BASE_URL` 은 **구버전 표기**다.
> 지금 운영에서 쓰는 것은 `API_INTERNAL_BASE_URL`·`NEXT_PUBLIC_SITE_URL` 이다.

### 12-5. 사업자번호 자리표시자

`estsw_admin` 의 `company_biz_num` 이 `000-00-00000` 이다.
`ProjectService.findUserRole` 이 **사업자번호 동일성으로** `COMPANY_AUTHOR`/`COMPANY_MEMBER` 를
가르기 때문에, 다른 기업에 같은 자리표시자가 들어가면 **같은 소속으로 오판정된다.**

실제 번호로 인증하려면 **FO 가 아니라 BO** 에서 한다 —
BO → 매니지먼트 → 유저 관리 → 소속 관리(`/management/company`) → 기업 상세 다이얼로그.
🔴 인증하면 `company_nm` 이 국세청 상호로 덮어써져 **"Ctrl + F" 가 사라진다.** 인증 후 기업명을 다시 고칠 것.
