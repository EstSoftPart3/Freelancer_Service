# 0장. 시작 전 준비

## 0-0. 🔴 먼저 알아둘 것 3가지

### (1) 로컬 DB = 실서버 DB 다

`docs/도구/*.py` 와 백엔드 `application.yml` 이 **전부 `db.estsw.co.kr:3306/freelancer_project`** 를 본다.
내 PC 에서 돌려도 **바뀌는 건 실서버 데이터**다.

> **"로컬에서 먼저 해본다"가 성립하지 않는다.**
> 그래서 모든 작업이 **① 백업 → ② 드라이런(미리보기) → ③ 눈으로 확인 → ④ 실행** 순서다.

### (2) Claude 는 쓰기 계열 명령을 직접 못 돌린다

Claude Code 의 auto mode 분류기가 DB·서버를 바꾸는 명령을 막는다.
드라이런·미리보기·검증은 Claude 가 대신 해주지만,
**등록·회수·`--apply` 는 사용자가 직접 실행**해야 한다.

실행하는 방법은 두 가지이고 **결과는 완전히 같다.**

| 방법 | 어떻게 |
|---|---|
| **A. Claude Code 프롬프트에서** | 입력창에 `!` 를 먼저 치고 명령을 붙인다 → 그 자리에서 실행되고 출력이 대화에 남는다 |
| **B. PowerShell 창에서** | `!` 를 **빼고** 명령만 붙여넣는다 |

> 이 문서의 명령에 붙은 `!` 는 A 방법 기준이다. **터미널에 직접 칠 때는 `!` 를 지우고** 붙여넣으면 된다.

### (3) 봇 계정이 먼저 있어야 한다

시더는 글쓴이를 `bot_01` ~ `bot_100` 계정 중에서 고른다
(조건: `user_id LIKE 'bot!_%' ESCAPE '!' AND user_type_cd = 301`).
**봇 계정이 없으면 등록이 통째로 실패**하고, 댓글 작성자 수 상한도 (계정 수 − 1) 로 묶인다.

지금은 봇 100개가 이미 만들어져 있다. 다시 만들 일은 **초기화(`cleanup-userdata.py`)를 같이 돌렸을 때뿐**이다.
그 경우에만 → `!python "C:/dev/Freelancer_Service/docs/도구/phase9-bot-accounts.py"`

  → **스크립트로 넣었으면 스크립트로 회수한다.**
- **API 에 `boardSqs` 를 안 주면 wide 모드로 봇이 쓴 글 전부가 내려간다**(`AdminSeedService.doRevoke`).

### 🔴 함정

- **재등록 전에 `seed-committed.json` 이 없어야 한다**(= `.done` 상태).

- **`balanceCategories` 는 `false` 여야 한다.** 서버 기본값은 `true` 인데,

  (`randomSeed` 만으로는 배분이 재현되지 않는다).
  스크립트는 알아서 하지만, **손으로 API 를 부를 때 가장 많이 걸리는 지점**이다.
- **여기서 작성일시가 확정되지 않는다.** `spreadMode=PAST` 로 과거에 흩뿌려질 뿐이다.
  원하는 날짜에 두려면 **반드시 3장을 이어서 한다.**

# 3장. 등록한 500건을 원하는 날짜 구간에 배치

> **선행** — 0-4(pymysql) · 0-7(백업) · 2장 등록 완료
> **백엔드는 필요 없다.** DB 를 직접 고친다.

### 무엇을 하는가

2장에서 "과거 아무 데나" 흩뿌려진 500건을 **원하는 날짜 구간(예: 9/1~9/28) 안, 08~23시**로 옮긴다.
**스크립트 2개를 순서대로** 돌리며, **순서가 바뀌면 안 된다.**

각 스크립트는

- **`--apply` 없이 = 드라이런** — 무엇이 얼마나 움직이는지 보여주기만 하고 아무것도 안 바꾼다
- **`--apply` 붙이면 = 실제 반영**

이라서, 항상 **드라이런 → 출력 확인 → apply** 로 두 번씩 친다.

### 1단계 — 게시글을 구간에 흩뿌린다 (답변·댓글도 같이 따라 움직인다)

```powershell
# 드라이런 (아무것도 안 바뀐다)
!python "C:/dev/Freelancer_Service/docs/도구/shift-seed-dates.py" --from 2026-09-01 --to 2026-09-28

# 출력이 납득되면 실제 반영
!python "C:/dev/Freelancer_Service/docs/도구/shift-seed-dates.py" --from 2026-09-01 --to 2026-09-28 --apply
```

### 2단계 — 구간 밖으로 밀려난 답변·댓글을 안으로 들인다

```powershell
# 드라이런
!python "C:/dev/Freelancer_Service/docs/도구/fit-seed-reply-dates.py" --to 2026-09-28

# 실제 반영
!python "C:/dev/Freelancer_Service/docs/도구/fit-seed-reply-dates.py" --to 2026-09-28 --apply
```

> `--from` / `--to` 만 바꾸면 **원하는 아무 구간이나** 된다. 기본값은 `2026-09-01 ~ 2026-09-28`.
> 2단계에 `--from` 이 없는 건 실수가 아니다 — 이유는 아래 부록에 있다.

### 성공했는지 확인하는 법

- 구간 초과 **0건**
- 새벽(08시 이전) 항목 **0건**
- **순서 역전 0건** — 글보다 이른 댓글·답변이 없어야 한다
- 2026-08-26 결과: 게시글 500 · 답변 244 · 댓글 2,112 이 **전부 9/1~9/28 · 08~23시** 안

## 3장 부록 — 왜 이렇게 복잡한가 (원리)

읽지 않아도 실행에는 지장 없지만, 값을 바꾸거나 문제가 생겼을 때 필요하다.

### 왜 등록과 날짜가 분리돼 있나

**시드 API 에 9월 날짜를 직접 줘도 서버가 오늘 날짜로 잘라낸다**(`AdminSeedService.java:343-346`).
"미래 글이 목록 상단에 영구히 눌러앉는" 사고를 막으려고 **일부러 넣은 방어**다.
DB 에 직접 쓰는 경로에는 그 방어가 없어서 → **API 로 넣고 → DB 에서 옮기는** 2단계가 됐다.

### 1단계 `shift-seed-dates.py` 가 지키는 것

- 글의 이동량(delta)을 **그 글의 답변·댓글에 똑같이 적용**한다.
  각각 따로 흩뿌리면 "글보다 먼저 달린 댓글"이 생긴다.
- 게시글 시각을 **08~23시**로 제한한다.
- `user_id LIKE 'bot!_%' ESCAPE '!'` 조건을 반드시 건다 — **실사용자 글은 건드리지 않는다.**
  (언더스코어는 LIKE 와일드카드라 ESCAPE 를 안 걸면 `botA…` 같은 실계정까지 걸린다.)
- 난수 시드가 고정(`RANDOM_SEED = 20260901`)이라 **같은 구간이면 몇 번을 돌려도 같은 배치**다.

### 🔴 2단계가 반드시 필요한 이유

1단계는 delta 를 그대로 더하기만 한다.
그래서 원래 글보다 한참 뒤에 달렸던 댓글은 **구간 밖으로 밀려난다.**
게다가 08~23시 제약이 **글에만** 걸려 있어 새벽 댓글이 생긴다.

2026-08-26 실측 — 글 500건은 9/1~9/28 안에 잘 들어갔는데:

| 대상 | 결과 |
|---|---|
| 댓글 | **295건(14%)** 이 9/28 초과, 최대 **2026-10-22 03:40** |
| 답변 | **25건(10%)** 이 9/28 초과, 최대 **2026-10-18 02:58** |
| 새벽 항목 | **618건** |

`fit-seed-reply-dates.py` 는 글 하나를 묶음으로 보고, 답변·댓글이 글에서 떨어진 정도를
**구간 끝까지 남은 만큼으로 비례 압축**한다. 같은 배율을 묶음 전체에 쓰므로
글→답변→답변댓글, 댓글→대댓글 **순서가 그대로 유지**된다.

계산은 **활동시간(08~24시, 하루 960분)만 세는 축**에서 한다.
실시간 축에서 압축하면 결과가 새벽으로 떨어질 수 있다 —
활동시간 축에서 계산해 되돌려야 반드시 08~23시가 된다.

`--from` 이 없는 이유: 각 답변·댓글을 **자기 글의 날짜에 앵커**해 구간 끝 쪽으로만 압축하므로
시작일은 알 필요가 없다. 게시글 테이블(`TBL_BOARD_M`)은 **아예 건드리지 않는다.**

# 문제가 생겼을 때

| 증상 | 원인 / 해결 |
|---|---|
| `'python'은(는) 내부 또는 외부 명령...` | 파이썬 미설치 또는 PATH 누락 → **0-3** |
| `ModuleNotFoundError: No module named 'pymysql'` | `pip install pymysql` → **0-4** |
| `pymysql 미설치. 먼저 실행: pip install pymysql` | 위와 같음 |
| 등록·회수에서 **연결 거부 / Connection refused** | 백엔드가 안 떠 있다 → **0-6**. 또는 `--base-url https://job.estsw.co.kr` 로 실서버 사용 |
| `회수할 기록이 없다` 로 멈춤 | `seed-committed.json` 이 `.done` 상태다. 다시 회수하려면 이름을 원래대로 되돌린다 |
| 등록이 건너뛰어짐 / 아무것도 안 들어감 | `seed-committed.json` 이 남아 있다. 1장 회수부터 다시 |
| 등록 자체가 실패한다 | 봇 계정이 없을 수 있다 → **0-0 (3)** |
| BO 회수 버튼에 글이 안 보인다 | 정상이다. 스크립트로 넣은 건 스크립트로 회수한다 → **1장 함정** |
| 카테고리가 균등해져 버렸다 | `balanceCategories` 가 true 로 갔다 → **2장 함정** |
| 400 에러 | `plannedAt` 을 안 실었다 → **2장 함정** |
| 날짜가 9월로 안 간다 | 서버가 미래를 잘라낸다. 3장을 이어서 해야 한다 → **3장 부록** |
| 뭔가 크게 잘못됐다 | `docs/도구/db-restore.py` 로 **0-7** 백업에서 복구 |
