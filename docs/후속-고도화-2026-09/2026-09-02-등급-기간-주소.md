## 확정된 규칙

### 등급 — 두 층 구조

공통코드 700 아래에 **13개**가 있다.

```
세부 9개   701 초초 LOW_LOW … 709 상상 HIGH_HIGH
대분류 3개 710 초급 LOW / 711 중급 MID / 712 상급 HIGH
등급 무관  713 ANY
```

- **화면에는 대분류 4개만** 보인다(초급·중급·상급·등급 무관).
  세부 9개는 마스터에 그대로 있고 「세부」를 켰을 때만 나온다.
- **검색 필터도 대분류 4개만** 노출한다. 세부로 등록된 옛 공고도 포함 관계로 잡힌다.
- **범위가 겹치는 등급은 함께 쓸 수 없다** — 「초초」와 「초급」은 겹친다. 「초초 · 중초」는 괜찮다.
  「등급 무관」은 아홉 등급을 전부 포괄하므로 이 규칙 하나로 자동으로 단독이 된다.

### 🔴 서열은 코드값이 아니라 영문명에서 나온다

`backend/.../project/util/DeveloperGradeSupport.java` 한 곳에 모았다.

```
rank(engNm) = major*3 + minor      major/minor: LOW=0, MID=1, HIGH=2
  LOW_LOW → 0    LOW(초급) → 0    ← 대분류는 그 구간의 하한
  HIGH_HIGH → 8  ANY → 없음(서열 밖)
```

**예전에는 `min(Long::compareTo)` 로 코드값이 곧 서열이라고 가정했다.**
세부 9개가 701~709 라 우연히 맞았을 뿐이고, 710(초급) 을 넣는 순간 초급이 최고 등급으로 뒤집힌다.
`TBL_COMMON_CODE_C` 에 정렬 컬럼이 없어서 생긴 구조다.
**등급을 새로 추가할 일이 있으면 영문명 규칙(`대분류_세부`)을 반드시 지킬 것.**

### 검색은 모집인원 행 기준

```sql
EXISTS (SELECT 1 FROM TBL_PROJECT_RECRUIT_HEADCOUNT_S h
        WHERE h.project_sq = p.project_sq AND h.developer_grade_cd IN (...))
OR ( NOT EXISTS (... h2.developer_grade_cd IS NOT NULL)     -- 인원 정보 없는 옛 공고
     AND p.project_developer_grade_cd IN (...) )
```

`ProjectMapper.xml` 세 곳. **대표 등급 컬럼(`project_developer_grade_cd`)은 목록 표시에 계속 쓰이므로 유지**한다.
여러 등급을 뽑는 공고가 이제 모든 해당 필터에 걸린다.

### 모집 인원 — 모드 통합

「등급별로 모집」/「총 인원으로 모집」 라디오를 없앴다. 등급마다 한 줄이고, **줄이 하나면 예전 총원 모드와 같다.**
`developer_grade_cd IS NULL` 은 더 이상 만들지 않는다(옛 데이터는 마이그레이션으로 채웠다).

### 수행 종료일 「미정」

`TBL_PROJECT_M.project_end_dt` 를 NULL 허용으로 풀었다. **플래그 컬럼 없이 순수 NULL** — 모집 인원 「미정」과 같은 방식.
`DateRangeModal` 은 모집 기간과 **공용**이라 `allowUndecidedEnd` prop 으로 수행 기간에서만 켠다.
🔴 **모집 종료일은 절대 미정이 될 수 없다** — D-day 계산의 근거다.

## 🔴 이번에 드러난 함정

### 1. 주소 좌표가 조용히 비었다 (운영 장애, 24시간 95건)

**다음 우편번호 검색은 좌표를 주지 않는다.** 주소를 고른 뒤 카카오 지오코딩을 *따로* 호출해 좌표를 채우는데,
성공했을 때만 넣고 실패하면 아무 일도 하지 않았다. 주소는 화면에 멀쩡히 보이는데 좌표만 빈 상태가 만들어지고,
그대로 제출돼 `latitude cannot be null` 로 터졌다.

같은 패턴이 **6곳**에 있었다(공고 등록·이력서·소속수정·정보수정·가입 폼 2개). 전부 고쳤다.
`lib/kakao.ts` 의 `loadKakaoMaps` 는 타임아웃 없이 무한 폴링이라 SDK 실패도 조용했다 → 10초 상한을 뒀다.

**교훈: 비동기로 채우는 값은 실패 경로를 반드시 사용자에게 알린다.**

### 2. 수정 폼이 주소 정보를 반만 복원했다

`findBySq` 가 `IFNULL(a1.latitude, a2.latitude)` 로 **두 주소의 좌표를 하나로 합쳐** 내려준다.
상세주소가 있으면 지하철 좌표가 통째로 가려진다. 게다가 `detailedZonecode` 는 SELECT 하면서
**resultMap 매핑이 없어 버려지고** 있었고, 시군구 코드는 조회조차 안 했다.

주소별로 나눠 내려주도록 고쳤다(`detailedLat/Lon`, `subwayLat/Lon`, 우편번호, 시군구).
**목록·지도가 쓰는 대표 좌표(`latitude`/`longitude`)는 그대로 둔다** — 용도가 다르다.

### 3. `disabled` 는 클릭 이벤트를 삼킨다

「세부」 체크를 못 풀게 `disabled` 로 막았더니, 눌러도 아무 반응이 없어 고장처럼 보였다.
**누를 수는 있게 두고, 눌렀을 때 이유를 알려준 뒤 상태를 되돌리는** 방식으로 바꿨다.

### 4. `<label>` 은 인라인이다

`space-y-1` 안에 `<label>` + `<select>` 를 넣으면 같은 줄에 붙는다.
다른 필드는 `Input` 이 `w-full` 이라 저절로 줄이 바뀌어 문제가 안 보였다. `block` 을 줘야 한다.
