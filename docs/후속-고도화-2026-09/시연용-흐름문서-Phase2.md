### 1-2. 한 줄 요약 (시연 멘트용)

- **실데이터만**: 내 제출 조회/저장, (숨겨진) 회사 추천
- **조건부 혼합**: 시장 평균·백분위·등수·히스토그램·스킬 상승률 — 같은 조건 실제 제출이 30건 미만일 때만 시드로 보충. 부족하면 지역 → 연차 순으로 조건을 넓히며, 직무·고용형태는 끝까지 고정
- **항상 혼합**: 순위표, 이직 동향 피드, 5년 추정 — 시드 필터 없음

### 1-3. 표본 확정 로직 (`SalaryService.resolveGroup`)

1. 직무+연차+지역+고용형태로 실표본 수 집계 → 30 미만이면 시드 포함해 조회
2. 그래도 30 미만 → **지역 조건 제거**(`relaxedConditions=["지역"]`) 후 반복
3. 그래도 30 미만 → **연차 조건도 제거**(`["지역","연차"]`)
4. 화면은 `sampleCount`(전체)·`realSampleCount`(실제)·`includesSeed`·`relaxedConditions`를 그대로 문구로 표기

### 1-4. 알려진 한계 (시연 중 질문 대비)

- **프리랜서 시드 480행**은 연 단위 금액이라 프리랜서 리포트가 왜곡됨(데이터 정책 미결, 4-A 보류 항목). 순위표는 재직자만이라 무영향
- 시드에 회사명·이직 정보가 없어 회사 추천은 시드를 섞을 수 없다 → 그래서 화면 보류
- 5년 추정의 성장률은 연차구간 사이를 3년 간격으로 근사, 2%~30%로 clamp
- 운영 DB에는 연봉 테이블·시드·소프트삭제 컬럼이 아직 없음(이관 트랙 별도)

### 1-5. 흐름도

```
[계산기] --localStorage--> [분석중] --POST /salary/submissions--> TBL_SALARY_SUBMISSION_M (+ _SKILL_S)
                                     └ 완료 후 → [리포트] GET /submissions/me + GET /report
[순위표] GET /salary/ranking (비로그인 공개)
BO /contents/salary: 목록·상세·등록(회원 지정=실 / 닉네임 지정=시드)·수정·소프트삭제
   └ 소프트삭제 → 위 표의 모든 통계에서 즉시 제외(순위표에서 빠지는 것 curl 검증)
```

## 2. 그 밖의 Phase2 기능 (실데이터/시드 관점)

| 기능 | FO 엔드포인트 | BO | 데이터 성격 |
|---|---|---|---|
| 게시판 재설계 (커리어/기술/기업/팀업/라운지) | `/{career\|tech\|company\|teamup\|lounge}`, `GET /community/board-categories` | `/admin/board` — 신규 5종 유형·필터·폼·답변 지원 | 오픈준비 시 봇 계정 100개로 **시드 500건**(`seed-community-500.py`)이 들어간 게시판. 신규 작성은 실데이터 |
| 투표 (IT 3250/일반 3251) | `GET/POST /votes`, `PATCH /{sq}`, `POST /{sq}/ballot` | `/admin/vote` — 참여자 있으면 옵션 변경 409, 소프트삭제 | 시드 컬럼 없음, 봇 계정이 작성자로 섞여 있음(아래 참고) |
| 면접후기 | `GET/POST /interviews`, `PATCH /{sq}` | `/admin/interview` — 소프트삭제·삭제 뱃지 | 〃 (등록 검증은 FO 서비스 재사용) |
| 연봉 | 위 1장 | `/admin/salary` | 실+시드 혼합(전용 `is_seed_yn` 컬럼 있음) |

**투표·면접후기는 연봉식 "시드" 개념이 없다** (2026-09-22 개발 DB 직접 조회로 확인, `freelancer_develop`).
`tbl_vote_m`/`tbl_interview_review_m`에 `is_seed_yn` 같은 컬럼 자체가 없고, 모든 행이 `user_sq`로
실제 계정(봇 계정 포함)에 연결된 진짜 게시물이다 — 통계 보정용 가상 데이터가 아니라 **봇 계정이
실유저처럼 작성해 둔 데모 콘텐츠**라는 뜻(게시판 500건 시드와 같은 계열).

| 테이블 | 건수 | 작성자 |
|---|---|---|
| `tbl_vote_m` | 5건 | admin×1, bot_01/03/07×1, qkdnf325×1 |
| `tbl_interview_review_m` | 12건 | admin×1, bot_01~10×1(10개), qkdnf325×1 |

시연 시 "이 투표/면접후기가 시드냐"고 물으면 **"봇 계정이 쓴 데모 글이고, 신규 작성은 실제
회원이 그대로 이어서 쓰는 같은 테이블"**이라고 답하면 된다(순위표처럼 별도 통계 로직이 붙어있지 않음).

## 3. BO 공통 정책 (시연 포인트)

- 삭제는 전부 **소프트삭제** + BO 목록엔 "삭제됨" 뱃지(감사용), FO에서는 숨김
- 등록·수정 검증은 FO 서비스 메서드를 재사용 → 규칙이 두 곳으로 갈라지지 않음
- BO 로그아웃은 서버 refreshToken 삭제 + 세션쿠키(브라우저 종료 시 자동 로그아웃)
- JWT 필터 예외 URL을 HTTP 메서드별로 좁힘(Dev 만료토큰 POST 500→401)
