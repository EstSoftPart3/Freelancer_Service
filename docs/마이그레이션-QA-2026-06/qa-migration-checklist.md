# 마이그레이션 통합 QA 체크리스트 (Vue → Next.js)

> 작성 기준일: 2026-06-29 · 통합 출처: check-auth-guards / check-login / check-account-recovery /
> check-project / check-alarm / check-mypage / check-mypage-company.
> **이 문서는 "지금 테스트를 실행"하는 게 아니라, 지금까지 발견한 내용을 브라우저 수동 테스트용
> 체크리스트로 정리한 것이다.** 실제 클릭/화면 확인은 이 문서 완성 후 별도 진행. 코드 수정·신규 검증 없음.
>
> ※ 섹션은 서비스 플로우 순서로 배열: 인증 → 계정복구 → 마이페이지-개인 → 프로젝트 → 마이페이지-기업 → 알람 → 미검증/갭.

## 요약

- **전체 체크 항목: 71개** (정상 동작 27 · 알려진 문제 39 · 미검증/갭 5)
- **확정된 P0: 7개** — 이력서 등록/수정 작동불능(3) · 기업 프로젝트 공고 등록 불가(1) · 프로젝트 지원·합격불합격·인터뷰 미구현(3)
- **미검증 영역: 4개** (게시판·Q&A·공지 CRUD, 메인/단순 조회성) + **알려진 갭 1개**(/affiliation 페이지 부재)

> 표기: `[정상]` 체크박스만 / `[문제]` 체크박스+원인+우선순위 / `[미검증]`·`[갭]` 별도 표시.
> 우선순위: **P0**=핵심 작동불능/미구현 · P1=명확한 누락·계약 위험 · P2=동작 미세차 · P3=경미/설계검토.

## 1. 인증 — 로그인 / 회원가입  (출처: check-login.md)

> **선행 조건:** 없음 — 의존성 시작점. 이게 막히면 이후 모든 섹션 테스트 불가.

### 정상 동작 (재현 확인용)
- [ ] 로그인 화면 → 개인/기업 토글 + 아이디·비번 입력 → 성공 시 "OOO님 안녕하세요" 알림 + `/` 이동
- [ ] 로그인 → 아이디저장/자동로그인 체크 → 다음 방문 시 해당 유형 아이디 자동 채움
- [ ] 회원가입(개인) → 아이디/비번/이름/생년월일/성별/휴대폰/주소/이메일인증/약관 전체 검증 통과 후 제출
- [ ] 회원가입 → 아이디 중복확인(GET /check-id, 디바운스 500ms) → 중복 시 "이미 사용 중"
- [ ] 이메일 인증 → 발송(POST /email/send-code) → 코드 확인(POST /email/verify-code)
- [ ] 보호 라우트 직접 URL 접근 → 토큰 없으면 `/login` 리다이렉트 (proxy.ts, 구현 확인됨 — Vue보다 견고)

### 알려진 문제
- [ ] 회원가입 → 제출 → **성공/실패 오탐 가능**. 원인: `SignUpController`가 `ApiResponse` 직접 반환 → 실패해도 HTTP 200, 에러는 body.status에만. Next는 2xx=성공 판정 → `body.status==='OK'` 검사 복원 필요. **P1** (백엔드 확정)
- [ ] 로그인 상태에서 뒤로가기로 `/login`·`/sign-up` 재진입 → **차단 안 됨**. 원인: proxy.ts에 `token && publicAuthPath → /` 규칙 없음. **P1**
- [ ] 기업 회원가입 → 대표자명·사업자번호·개업일 3종 **필수 입력 강제**. 원인: Next만 임의 필수화, 백엔드 DTO는 optional·미저장 → 기획 의도 확인 필요(필수 유지 시 백엔드 저장 추가). **P1(기획확인)**
- [ ] 새로고침 후 → 로그인 사용자도 첫 렌더가 비로그인 UI로 깜빡임. 원인: Zustand `persist` 없음, `/me` 비동기 복원. **P2(상태관리 트랙)**
- [ ] 로그인 유형 "마지막 선택 기억" → Vue만큼 동작 안 함. 원인: 토글 시 유형 미저장 + 마운트 복원 키 불일치(`savedLoginType`). **P2**
- [ ] 소셜 로그인 버튼 → 제공자 표현 오류. 원인: `DOMAIN_PROVIDERS`(이메일 도메인)를 소셜 버튼으로 렌더(kakao/naver/google/apple 아님). 현재 '준비 중' 알림이라 기능 영향은 없음. **P2**
- [ ] 기업 회원가입 → 담당자 이름 2자 미만 검증 누락(빈값만 검사). **P2**
- [ ] 회원가입 → 약관 동의 모달 미구현(체크박스만, 약관 본문 미표시). **P2**

> **여기서 막히면:** 이후 모든 섹션 테스트 보류, 막힌 항목만 체크리스트에 기록 후 다음 작업 일정에서 재시도.

## 2. 계정복구 — 아이디찾기 / 비밀번호 재설정  (출처: check-account-recovery.md)

> **선행 조건:** 1번 인증 화면에 접근 가능해야 함(로그인은 불필요 — 비로그인 상태에서 진입하는 인증의 부속 플로우).

### 정상 동작
- [ ] 아이디찾기 → 이름+이메일 인증 → 계정 있으면 결과 페이지로, 없으면 "일치하는 회원 정보를 찾을 수 없습니다"
- [ ] 비번재설정 STEP-A(본인확인) → 아이디+이름+이메일 인증 → 성공 시 `/reset-password` 이동
- [ ] 비번재설정 STEP-B(새 비번) → 정규식+확인 일치 → POST /reset-password(쿠키 세션) → 성공 시 `/login`
- [ ] 재설정 토큰 4분기(유효/만료/사용됨/위조) → 전부 백엔드 쿠키 세션에 위임(양쪽 동일, 회귀 없음)

### 알려진 문제
- [ ] 아이디찾기 결과 화면 → **가입일이 빈칸 + 구분(userType) 누락**. 원인: Next가 `regDt`를 읽으나 실제 응답 필드명은 `userCreatedAtDtm`(백엔드 확정), userType 미표시. → `regDt→userCreatedAtDtm` 교정 + 구분 컬럼·날짜 포맷 복원. **P1**
- [ ] 비번재설정 STEP-A → 아이디(≥4자)·이름(≥2자) 길이 검증 누락(빈값만 검사). **P1**
- [ ] 아이디찾기 결과 없음 시 → 로그인/비번찾기 버튼 노출 차이(Next 항상 노출 vs Vue 숨김). **P2**
- [ ] STEP-A 이메일 도메인 목록 불일치(Vue=naver/gmail/yahoo vs Next 공용=naver/gmail/daum/nate/hotmail, yahoo 누락). **P2**
- [ ] 아이디찾기 결과 `?output=` → PII(userId/userNm)가 SSR HTML/서버 로그/URL에 노출. 원인: Next 서버 컴포넌트 파싱. **P3**
- [ ] `/reset-password` 직접 URL 진입 → 세션 미검증 폼 렌더(양쪽 동일, 제출은 백엔드가 거부). **P3(백엔드 경계 백로그 연계)**

> **여기서 막히면:** 계정복구는 인증의 부속 플로우 — 막혀도 본 인증(로그인)이 통과되면 이후 섹션은 진행 가능. 막힌 항목만 기록.

## 3. 마이페이지 — 개인 전용  (출처: check-mypage.md)

> **선행 조건:** 1번 인증 통과 필요(로그인된 개인 계정).

### 정상 동작
- [ ] 이력서 목록 조회(GET /mypage/resume/list) → 대표 설정 → 삭제
- [ ] 소속 정보 조회(GET /mypage/applications/info) → 탈퇴(PATCH .../withdraw)
- [ ] 소속 지원현황 조회(GET /mypage/applications/user) → 필터(all/read/unread)·검색·지원취소
- [ ] 소속 스크랩 조회(GET /mypage/applications/scraps) → 검색·삭제

### 알려진 문제
- [ ] **이력서 등록/수정 → 저장 → 완전 작동불능(★P0).** 원인 3겹: ①경로 불일치 — Next `POST /mypage/resume/new`·`PUT .../update/{sq}`·`GET .../detail/{sq}` vs 백엔드 루트 `POST /mypage/resume`·`PUT|GET /mypage/resume/{sq}` → **404로 본문 전체 폐기** ②Content-Type — 백엔드 multipart(@RequestPart) 기대 vs Next 순수 JSON → 415 ③필드명 5+종(education→educationList 등)·항목 내부구조(교육이력·자격증)·주소 평면↔중첩 불일치. (check-mypage.md §2) **P0**
- [ ] 이력서 폼 → 입력 항목 3종(프로필 사진·첨부파일·프로젝트 이력) 자체가 없음 → 저장해도 항상 null. **P0**
- [ ] 이력서 폼 → 유효성 검증 0건(필수·전화/이메일 정규식·파일용량 전무). **P0**
- [ ] 이력서 신규 등록 → 회원 기본정보 자동기입(GET /mypage/edit/info) 누락(빈 폼). **P1**
- [ ] 소속 지원현황/스크랩 → 회사명 클릭 상세 모달 미이관(클릭 불가 span). **P1**
- [ ] 이력서 목록 → 제목 클릭 상세 모달(ResumeDetailModal) 미이관(수정 페이지로 이동). **P1**
- [ ] 이력서 복사 → 파일 포함/제외 선택 누락(항상 포함 하드코딩). **P1**
- [ ] 소속 탈퇴 후 → 소속 플래그 미갱신(clearUser 호출 누락, 새로고침 전까지 stale). **P1**
- [ ] 성공 판정 방식이 Next 내부에서 제각각(HTTP vs body.status — 이력서 삭제·스크랩은 HTTP만, 지원취소는 status 검사). **P2**

> **여기서 막히면:** 이력서 작성이 막히면 4번 프로젝트의 '지원' 플로우는 의미가 제한됨 — 단, 프로젝트 목록/상세 조회 등 독립 항목은 진행 가능. 막힌 항목만 기록.

## 4. 프로젝트 — 지원 / 합격·불합격 / 인터뷰  (출처: check-project.md)

> **선행 조건:** 3번 이력서 작성 가능해야 의미 있음 (단, 이력서가 막혀 있어도 프로젝트 목록 조회 등 일부 항목은 독립적으로 테스트 가능).

### 정상 동작
- [ ] 프로젝트 상세 조회(GET /projects/{sq}/details) → 모집중/마감/지원완료 버튼 분기 표시
- [ ] COMPANY_AUTHOR → 공고 수정 이동 / 삭제(DELETE /projects/{sq})
- [ ] 프로젝트 상세 → 스크랩 토글(POST /projects/{sq}/scraps)
- [ ] 본인 지원현황 목록(GET /projects/applications[/corporate]) → 지원취소(PATCH, 확인모달 경유)
- [ ] 인터뷰 확정 상태 → 확정 날짜 배지 읽기전용 표시

### 알려진 문제
- [ ] **프로젝트 상세 → "지원하기" → 지원 확정 → 미구현(★P0).** 원인: handleApply가 `toast.info('지원하기 기능은 준비 중입니다.')` 스텁. ResumeSelectModal·AffiliationMemberModal·`POST /projects/applications/{sq}`·중복지원 체크 전부 부재. **P0**
- [ ] **회사 → 공고 지원현황 → 합격/불합격 처리 → 미구현(★P0).** 원인: 공고 목록에 "지원현황" 진입 버튼 없음, ApplyStatusModal·ResumeDetailModal·`updateStatus(인터뷰요청중/불합격)` 전부 부재. ※마이페이지 "지원자 현황"(§4)의 합격처리는 **별경로로 구현됨** — 혼동 주의. **P0**
- [ ] **인터뷰 시간 확정 → 미구현(★P0).** 원인: '인터뷰요청중'이 액션 없는 배지뿐, InterviewSelectModal·`PATCH /projects/applications/interviews/{slotSq}` 부재(개인·기업 양 경로). **P0**
- [ ] 스크랩 요청 바디 `target` 리터럴: Next `'project'` vs Vue `'프로젝트'`(한글). 백엔드 기대값 확인 후 일치 필요(불일치 시 스크랩 깨짐). **P1**
- [ ] 모집 마감 표현: Next는 마감 시 지원/스크랩 버튼을 숨김(Vue는 "지원 마감" 비활성 버튼 표시). **P2**
- [ ] `isRecruitmentEnded` 경계: Next는 `T23:59:59` 미부가 → 마감일 자정 기준으로 약 하루 일찍 마감. **P2**
- [ ] COMPANY_MEMBER 버튼 의미 역전: 차단 문구 제거 + 정상 "지원하기" 버튼 부여(원본버그-Next처리). **P2**

> **여기서 막히면:** 지원/합격불합격/인터뷰는 이미 P0 미구현으로 확정 — 재현 확인만 하고, 조회성 항목 위주로 통과 여부 기록.

## 5. 마이페이지 — 기업 전용  (출처: check-mypage-company.md)

> **선행 조건:** 1번 인증을 기업 계정으로 통과 필요(개인 계정과 별도 로그인).

> ★대비: 이력서의 3겹(경로→Content-Type→필드명) 패턴은 **기업 폼에서 재현 안 됨** — 제출 계약은 일치.
> 깨지는 곳은 **프로젝트 폼 '로드' 단계 한 곳**뿐.

### 정상 동작 (제출 계약 일치 확인됨)
- [ ] 프로젝트 공고 목록(GET /projects/companies, .../status) → 필터·검색·삭제(DELETE /projects/{sq})
- [ ] 소속 지원자 현황(GET /mypage/applications/company) → 열람 처리 → **합격(502)/불합격(503)** 처리(PUT .../apply/{sq}) ※경로·Content-Type·필드명 일치
- [ ] 소속 인원 관리(GET /companies) → 퇴사 처리(PATCH /companies, {userSq,newStatus})
- [ ] 소속 정보 수정(GET/POST /mypage/edit/affiliation/*) → 텍스트 저장·프로필이미지 업로드(multipart)/삭제·모집 해제

### 알려진 문제
- [ ] **프로젝트 공고 등록/수정 → 사용/우대 기술 선택 → 등록 → 사실상 등록 불가(★P0).** 원인: GET /projects/forms의 `skills`가 그룹 객체(`{parentSkillTagNm, childSkillTagNms[]}`)인데 Next가 평면 `string[]`로 가정 → `s.toLowerCase()`로 스킬 피커가 렌더 중 붕괴 → usingSkills/preferSkills 빈 채 제출 → 백엔드 `@NotEmpty` 위반 → **모든 등록/수정 400**. (제출 경로·CT·필드명 자체는 일치) **P0**
- [ ] 프로젝트 폼 → 인터뷰 가능 시간 선택 전체 부재(Next `interviewTime:[]` 하드코딩, InterviewTimeModal 미이관). **P1**
- [ ] 프로젝트 폼 → 지하철역 검색 비작동(입력 readOnly + "미구현" placeholder, SubwaySearchModal 미이관). **P1**
- [ ] 프로젝트 폼 → 지역(시/구) 캐스케이드 셀렉트 제거(우편번호로 축소). **P1**
- [ ] 프로젝트 폼 → 제출 검증 갭(단가·근무형태·직군·사용/우대기술·상세내용 미검증 → 백엔드 400 유발). **P2**
- [ ] 프로젝트 수정 프리필 → 우편번호/시군구 미복원(ExistProjectVo에 detailedZonecode/SigunguCode 필드 부재, 양쪽 공통 한계). **P3**

## 6. 알람(알림)  (출처: check-alarm.md)

> **선행 조건:** 위 액션들(지원·합격 등)이 수행돼 알림이 생성돼 있어야 일부 항목 확인 가능(없으면 빈 목록 기준으로만 확인). 알림은 위 액션들의 부산물이라 가장 나중.

### 정상 동작 (충실 이식 — 깨끗)
- [ ] 헤더 알림 → 목록 조회(GET /notifications) + 안읽음 수(unread-count) → 벨 dot/배지 표시
- [ ] 알림 클릭 → notificationTargetUrl 이동 + 읽음 처리(PATCH /notifications/{sq}) + 안읽음 수 재조회
- [ ] 모두 읽음(PATCH /notifications) · 전체 삭제(DELETE /notifications) · 단건 삭제(DELETE /notifications/{sq})
- [ ] 빈 상태 표시 · Optimistic UI · 삭제 버튼 전파 차단

### 알려진 문제
- [ ] 알림 클릭 시 저장된 `notificationTargetUrl`이 Vue 구경로(camelCase, 예 `/projectListPage`)면 Next에서 404. 원인: **백엔드 저장값**(프론트 경로 생성 로직은 동일·정상). 댓글 알림(`/board/:sq`)은 경로 불변이라 안전. **중(백엔드 백로그)**
- [ ] 알림 실시간성 없음(폴링·SSE·WebSocket 없음, 패널 재오픈 시에도 재조회 안 함). 양쪽 동일 → 회귀 아님. **낮(원본 한계)**

> **여기서 막히면:** 알림은 부산물 — 막혀도 다른 섹션에 영향 없음. 막힌 항목만 기록.
